---
description: セールスレターを書いて、合格するまで診断ループを回す
---

`notes/$1/` のセールスレターを、ゲートを通過するまで自動で仕上げます。

## 手順

### 1. 商品の型を確認する

**`notes/$1/00-concept.md` の `productType` を最初に読みます。**

書かれていなければ**停止**し、`product-concept` の実行を促します。
型が決まっていないとレターの構造も判定基準も決まりません。

| 型 | 再現性の根拠 | `profile.md` |
|---|---|---|
| `tool`（道具型） | 成果物そのものの検証可能性 | **不要** |
| `experience`（体験談型） | 書き手の実績 | **必須** |

### 2. 入力を確認する

| ファイル | tool | experience |
|---|:---:|:---:|
| `notes/$1/00-concept.md` | 必須 | 必須 |
| **`notes/$1/pricing.json`** | **必須** | **必須** |
| `knowledge/account.md` | 必須 | 必須 |
| `knowledge/voice.md` | 必須 | 必須 |
| `research/accounts/{genre}.md` | 任意 | 任意 |
| `knowledge/profile.md` の実数値 | 参照のみ | **必須** |

**`pricing.json` が無ければ停止し、`pricing-strategy` の実行を促します。**
価格と天井が決まっていないと C3（今買う理由）と C4（高い）を判定できません。

`research/accounts/{genre}.md` は現行カテゴリ向けの調査がまだありません。
無い場合は警告して続行し、`market/{date}.md` の有料率と上位記事で代替します。

`type: experience` で `profile.md` に実数値がなければ**停止**します。
数字のないレターは再現性を作れません。

**`profile.md` が空のうちは `type: tool` だけを扱ってください。**

### 3. `sales-letter` を実行（`letter-writer` サブエージェント）

- `02-letter.md` と `letter-meta.json` を生成
- `type: tool` では `letter-meta.json` に `toolEvidence` を必ず出力する

### 4. 診断ループ（最大2周）

**`critic` に `pricing.json` を渡さないでください。** 価格はレター本文に書かれており、
critic は読者と同じ情報だけで C3（今買う理由）と C4（高い）を判定します。
価格の狙いを渡すと、判定が売り手の都合に寄ります（CLAUDE.md「サブエージェントに渡してよい情報」）。

```
letter-audit を critic サブエージェント（Opus 5）で実行
  → audit.json の pass が true なら抜ける
  → false なら failures だけを letter-writer に渡して差し戻す
  → 2周で通らなければ打ち切り、上流の見直しを提案する
```

**`failures` だけを渡してください。** 全文の書き直しを指示すると、
○だった項目が壊れて振り出しに戻ります。

**2周で通らないときは、疑わしい上流工程を名指しします。**

| 残った項目 | 疑う上流 |
|---|---|
| C2（再現性） | `product-concept` — 型が合っていない。`tool` にすべきものを `experience` にしていないか |
| C3（今買う理由） | `pricing-strategy` — 本物の期限や値上げ計画が無い |
| C4（高い） | `pricing-strategy` — 価格と中身が釣り合っていない |
| C5（自分には早い） | `account-design` — 対象読者が広すぎる |
| B3（客層） | `weekly-research` — テーマ選定の段階でずれている |

### 5. `ethics-line` を実行（`auditor` サブエージェント / full モード）

- **回数制限なし。** `clear: true` になるまで繰り返す
- `severity: review` の項目は修正せず、人間への確認事項として残す

### 6. 報告

## 報告の形式

```
レター完成 — $1

型: tool（道具型）
診断: 合格（16/16） / 1周

線引き: 1件を修正
  E3 「多くの人が使っています」を削除（母数の根拠が profile.md にない）

要確認: 1件
  E1 「今月中は据え置き」— 値上げ予定が未確定。実行するなら残す
```

不合格で打ち切った場合:

```
レターが2周で通りませんでした — $1

残った項目: C2（再現性がなさそう）
  該当行: 44-52
  状態: 成果物の中身が開示されていない。件数だけを書いている

上流の見直しを推奨します:
  product-concept — 何を渡す商品なのかが確定していない可能性があります。
  道具型では「実物の断片を見せること」が再現性の根拠そのものです。
```

## 道具型でよく落ちる項目

| 項目 | 原因 | 直し方 |
|---|---|---|
| C2 | 目次だけ見せて中身を隠した | 実物の断片を数行そのまま載せる |
| C2 | 動作条件を書いていない | 「何があれば動くか」を明記する |
| C2 | 最初の1歩がない | 「まずこれをコピーする」を書く |
| A3 | 再現性が2つしかない | 単純化・簡易化・成果物の開示・不便だった状況の4つを揃える |

**道具型で C2 が×になるのは、ほぼ例外なく中身を出し惜しみしたときです。**
