# コンセプト

テンプレ丸出しの画面しか出せない人に、design.md雛形＋用途別4指示テンプレートを渡し、AIに毎回同じ品質のUIを出させる型を提供する道具型商品。

## 型の根拠

productType: tool

- profile.md の実績: なし（AI技術ジャンルでの実績は現時点でゼロ）
- 同ジャンルか: 該当なし
- 自分以外の結果: なし
- → 判定: profile.md が空のため、判定手順を踏むまでもなく tool で確定。

## 3要素

- 強み: account.md サブ①（AI×Webデザイン）。無料記事（2026-08-11-ui-3points）で見せた「余白・階層・色数」の直し方を、毎回同じ品質で出させる型としてテンプレート化できる
- 競合の穴: market/2026-08-09.json でUIデザインは gapScore 7.246（需要86.5/供給11.9件/日）と計測タグ中最上位帯だが、paidRatio は 0.01 と極端に低い。Webデザインも gapScore 2.971・paidRatio 0.081。売っている人が少ない領域であり、`design.md` 雛形をコピー可能な形で配布している商品は競合調査（research/accounts/ 配下）に見当たらない
- 深層心理: account.md のペルソナ「本当は: 人に見せたときに恥ずかしくないものを、毎回出せるようになりたい」に対応する。単発の直し方ではなく「型」を渡す点で、無料記事の1回限りの解決とは別の価値を持つ

## 渡すもの

- 形式: design.md雛形（Markdownテンプレート、コピーしてそのまま使える完全版）／用途別指示テンプレート4種（LP・管理画面・ダッシュボード・フォーム）／before/after作例（無料記事 2026-08-11-ui-3points のデモを土台に、有料部分では別対象（フォーム）の作例を追加する）
- 点数: design.md雛形1つ＋指示テンプレート4種＋before/after作例2種（管理画面・フォーム）＝計7点
- 動作条件: Claude Code（またはClaude Desktop/Web）でプロジェクトルートに `design.md` を置き、`@design.md` で参照させる形で動作確認済みの構成を前提とする。他のAIツールでも「設計方針を先に読ませる」という考え方自体は転用できるが、本商品内の検証はClaude Code前提で行う
- 最初の1歩: `design.md` をプロジェクトルートに置き、最初のUI生成プロンプトの冒頭に「`@design.md` を読んでから、以下の指示に従ってください」と書く
- できないこと: 既存ブランドガイドラインへの厳密な準拠（別途カスタマイズが要る）。コードの実装バグ修正は扱わない（見た目の設計方針の指示に限る）。生成AIの出力そのものを保証しない（テンプレートは指示の質を上げるものであり、モデルの出力を完全に制御するものではない）

## 構成

### 無料部分（2000字）
無料記事（2026-08-11-ui-3points）で見せた「3箇所を直す」考え方を要約し、指示テンプレート4種のうち1種（管理画面用）を全文で公開する。design.md雛形は見出しと項目名だけを見せ、中身は有料部分に置く。

### 有料部分（5000〜8000字）
1. design.md雛形の全文（コピーしてそのまま使える完全版）
2. 用途別指示テンプレート3種（LP・ダッシュボード・フォーム。管理画面は無料部分で公開済み）
3. フォームのbefore/after作例と、投げた指示の全文
4. 動作条件と最初の1歩
5. できないこと

## 対象読者

account.md のペルソナのうち、「AIに指示して動くものは作れたが、出てきた画面がテンプレ丸出しで人に見せられなかった人」で、かつ**複数の画面を継続的に作る立場**（副業の受託・自社サービスの複数画面を1人で作っている等）に絞る。単発の1画面だけを直したい読者は無料記事で足りるため、有料部分は「型」を繰り返し使う人に向ける。
