# product-concept

**有料noteのフローはここから始まる。** 型が決まっていないと、レターの構造も
判定基準も決まらない。

---

## 何を決めるスキルか

| 決めること | なぜここで決めるか |
|---|---|
| **`productType`** | `sales-letter` の再現性③④、`letter-audit` の判定基準が分岐する |
| コンセプト1文 | 全工程がこの1文に従う。ぶれると `letter-audit` の C2 が通らない |
| 何を渡すか（成果物の実体） | **道具型ではこれが再現性の根拠そのもの** |
| 構成 | 無料部分と有料部分の切れ目 |
| 対象読者の絞り | `letter-audit` の C5（自分には早い）に直結する |

**価格は決めない。** `pricing-strategy` の担当である。

---

## 入力

| ファイル | 必須 | 何に使うか |
|---|:---:|---|
| `notes/{slug}/00-theme.md` | ○ | テーマと `productTypeHint` |
| `knowledge/account.md` | ○ | 主カテゴリ・サブカテゴリ・ペルソナ |
| `knowledge/profile.md` | ○ | **型の判定に使う。空なら `tool` 一択** |
| `research/market/{最新}.md` | — | 需要÷供給の高い領域。有料率。無ければ警告して続行 |
| `research/accounts/{genre}.md` | — | 競合の商品。無ければ警告して続行 |

`00-theme.md` が無ければ**停止して `daily-article` か `weekly-research` を促す。**
テーマが決まっていない状態でコンセプトを作らない。

---

## 1. `productType` を確定する

**これが最初で、最重要である。**

| 型 | 再現性の根拠 | `profile.md` | 例 |
|---|---|---|---|
| `tool`（道具型） | **成果物そのものの検証可能性** | **不要** | スキル定義集、プロンプト集、設計図、テンプレート |
| `experience`（体験談型） | 書き手の実績 | **必須** | 「月5万を達成した手順」 |

### 判定手順

```
1. profile.md の「実績」に、この商品の主張を支える実数値があるか
     無い → tool で確定。ここで終わり
     有る → 2 へ

2. その実数値は、この商品と同じジャンルで得たものか
     違う → tool で確定
       （例: 旧ジャンルのフォロワー数は AI技術商品の根拠にならない）
     同じ → 3 へ

3. profile.md に「自分以外の結果」が1つ以上あるか
     無い → tool で確定（experience は再現性③が作れない）
     有る → experience を選んでよい
```

**`profile.md` が空のうちは、この手順を踏むまでもなく `tool` である。**

### 迷ったら `tool` にする

道具型は「買った人が手元でコピペして動かせるか」で再現性を担保する。
書き手が何者かは関係ない。**動くかどうかはコードとテンプレートが証明する。**

体験談型を選んで実績が足りないと、`letter-audit` の C2（再現性）と
`ethics-line` の E3（裏付けのない実績）で必ず止まる。**時間の無駄になる。**

---

## 2. コンセプトを1文で書く

**強み × 競合の穴 × 深層心理 の交点**を1文にする。

```
✕ 「Claude Code の使い方を解説します」
    → 強みも穴も深層心理も無い。ただの説明

✕ 「AI活用の決定版パッケージ」
    → 抽象的。誰の何が解決するのか分からない

○ 「テンプレ丸出しの管理画面を、余白と階層の5ルールだけで
    人に見せられる画面にする指示テンプレート集」
    → 強み（設計指示）× 穴（AIにデザインを直させる手順が無い）
      × 深層心理（作れるのに見せられない）
```

### 3要素が入っているかを自分で確認する

| 要素 | 確認 |
|---|---|
| 強み | `account.md` のサブカテゴリのど真ん中にあるか |
| 競合の穴 | `market/{date}.md` で需要÷供給が高い領域か。競合が answer していないか |
| 深層心理 | `account.md` のペルソナの「本当は」に触れているか |

**1つでも欠けたら書き直す。** 3要素が揃わないコンセプトは、レターの段階で必ず崩れる。

---

## 3. 何を渡すかを決める（道具型では最重要）

**「目次」ではなく「実体」を決める。**

```
✕ 「デザインの原則を解説した章」        → 実体がない
○ 「そのままコピーして使える指示テンプレート12個（Markdown）」
✕ 「自動化のノウハウ」                  → 実体がない
○ 「GASコード5本（議事録要約 / 定期通知 / スプレッドシート集計 / …）」
```

決めること。

| 項目 | なぜ必要か |
|---|---|
| **成果物の形式** | コード / テンプレート / プロンプト / 設計図。何を渡すのか |
| **点数と分量** | 「12個」「5本」。数えられる形にする |
| **動作条件** | 何があれば動くか。これが無いと「動かない」というクレームになる |
| **最初の1歩** | 買った人が最初に実行する具体的な手順 |
| **できないこと** | 適用範囲の外。書かないと信用を失う |

**この5つが埋まらないなら、商品として成立していない。** テーマ選定に戻る。

---

## 4. 構成を決める（無料部分と有料部分の切れ目）

| 部分 | 分量 | 中身 |
|---|---|---|
| 無料部分（`02-letter.md`） | 2000字 | セールスレター。**実物の断片を数行そのまま見せる** |
| 有料部分（`03-draft.md`） | 5000〜8000字 | 成果物の全体と手順 |

**切れ目の原則: 出し惜しみしない。**

無料部分で実物の断片を見せないと、`letter-audit` の C2（再現性がなさそう）が
ほぼ例外なく×になる。**道具型で C2 が落ちるのは、中身を隠したときである。**

見せる断片と隠す全体の比率は、おおよそ「1割を見せて9割を渡す」。

---

**`productType` を先頭に書く。書かれていないと後続が停止する。**

```markdown

productType: tool

---

# コンセプト

{1文}

## 型の根拠

productType: tool

- profile.md の実績: {あり／なし。あるなら何が}
- 同ジャンルか: {判定}
- 自分以外の結果: {あり／なし}
- → 判定: {理由を1文で}

## 3要素

- 強み: {account.md のどのサブカテゴリか}
- 競合の穴: {market/{date}.md のタグ名と需要÷供給の数値を引用する}
- 深層心理: {ペルソナの「本当は」のどれか}

## 渡すもの

- 形式: {コード / テンプレート / プロンプト / 設計図}
- 点数: {数えられる形で}
- 動作条件: {何があれば動くか}
- 最初の1歩: {買った人が最初にやること}
- できないこと: {適用範囲の外}

## 構成

### 無料部分（2000字）
{見せる実物の断片を明記する}

### 有料部分（5000〜8000字）

...

{account.md のペルソナをこの商品に合わせて絞ったもの}

```

---

## 物差し（これを満たさなければ出力しない）

**自己評価ではない。構造的な充足の確認である。**

| # | 条件 | 満たさないとき |
|---|---|---|
| 1 | `productType` が判定手順に沿って決まっている | 手順1からやり直す |
| 2 | コンセプト1文に3要素が全て入っている | 書き直す |
| 3 | 競合の穴が `market` の数値で裏付けられている | 印象で書かない。数値を引用する |
| 4 | 「渡すもの」の5項目が全て埋まっている | **商品として成立していない。テーマ選定に戻る** |
| 5 | 無料部分で見せる実物の断片が決まっている | 決める。隠すと C2 が落ちる |
| 6 | `profile.md` が空なのに `experience` を選んでいない | `tool` に変える |

**4 が埋まらないときは停止して報告する。** 埋めるために創作しない。

---

## やらないこと

- **価格を決めない。** `pricing-strategy` の担当である
- **レターを書かない。** `sales-letter` の担当である
- **本文を書かない。** `draft-writing` の担当である
- **良し悪しを自己評価しない。** 判定は `critic` と `auditor` が行う
- **`profile.md` に無い実績を前提にしたコンセプトを作らない**

---

## 次に渡すもの

```
00-concept.md
  ↓
pricing-strategy  → 価格を決める
  ↓
sales-letter（letter-writer）→ 02-letter.md
draft-writing（writer）      → 03-draft.md
```

**`pricing-strategy` を飛ばさない。** 価格が決まっていないと
`letter-audit` の C3（今買う理由）と C4（高い）が判定できない。
