あなたは note の見出し画像を専門とするアートディレクターです。
以下の条件で16:9の画像を1枚作ってください。

## 被写体（最重要）
暗い作業机の上に、2枚の薄いガラス板が少し間隔をあけて立てかけられている。
・手前の板：琥珀色に発光する小さな立方体が整然と格子状に並んでいる。輪郭がはっきりしている
・奥の板：紫と青の光がにじんでいて、形が曖昧。ピントが合っていない
2枚の板は同じ大きさ・同じ角度で、手前が主役だと分かる配置。

## 構図
・2枚の板を画面の左寄りに配置する
・右側の約4割を、平坦で暗い余白として空ける
・視線が奥の板から手前の板へ自然に移動する角度
・浅い被写界深度。奥の板と背景は軽くぼかす

## 色
・背景の基調: #12111b（わずかに紫を含む暗色）
・アクセント: #ffb43d（琥珀）。この1色だけを使う
・コントラストを強く。中間色を多用しない
・紫はぼけた奥の板にだけ許可する

## 質感とライティング
・Apple の製品ページのようなプロダクト写真
・斜め右上からの単一光源。影の方向をすべて揃える
・ガラスの厚みと縁の反射を描写する
・高精細、ノイズなし、4K品質

## テキスト
画像内に文字を一切入れないでください。
note ではタイトルが画像の上に重なるため、
右側に文字を置ける平坦な余白を確保してください。

## 避けるもの
・グラデーションを全面に敷くこと
・複数の光源で影の方向がばらつくこと
・要素を3つ以上並べること
・脳のイラスト、光る回路基板、ロボットの手、青い網目状のネットワーク
・ノートPCの前に座る人物
・カラフルなUIパーツが空中に散乱している構図
・板の中に実際の文字やUIラベルを描き込むこと

AI に LP を作らせると、それらしいものが出てきます。

紫のグラデーション、中央寄せの大きな見出し、絵文字つきのバッジ、影のついたボタン。

動いてはいるのに、人に見せる気になれない。

ここで多くの人は「引き算」をします。色を減らし、影を消し、余白を整える。

それだけだと、整った代わりに退屈になります。

削るのは3手。そのあとに、効かせる1手が要ります。

「それらしい」で止まる理由

生成された画面を見て、どこが悪いのか言葉にできないことがあります。

崩れてはいません。文字も読めます。ボタンも押せます。

それでも、自分で作ったものとして人に出すには足りない。

この状態のとき、多くの場合は要素が足りないのではなく、多すぎます。

AI は指示された情報をすべて画面に載せようとします。バッジも、見出しも、
リード文も、特徴の3項目も、ボタンも、注意書きも、全部を同じ強さで置きます。

結果として、どこから読めばいいのか分からない画面になります。

作例を用意しました。左が AI の出力そのまま、右が直したものです。

https://kou56250046-cloud.github.io/note-automation-app/demo/2026-08-07-lp-firstview/

同じ情報量ではありません。右は削って、そのぶんを1箇所に足しています。

順番は、余白、視線、色、そして最後に足す1手です。

色から手を付けると、配色を変えるたびに全体の印象が変わって、
どこが効いたのか分からなくなります。構造を整えてから色を決めます。

手1: 余白に緩急をつける

最初に見るのは余白です。

理由は2つあります。1つは、余白がいちばん多く画面を占めているからです。
もう1つは、余白の指定が機械的に数えられるからです。

「この配色は良いか」は判断が要りますが、「マージンが全部同じ値か」は数えれば分かります。

判断の要らないところから手を付けます。

作例の before では、こうなっていました。

.badge { margin-bottom: 20px; }
h1     { margin-bottom: 20px; }
.lead  { margin-bottom: 20px; }
.points{ margin-bottom: 20px; }
.cta   { margin-bottom: 20px; }

すべて 20px です。

余白が均一だと、どの要素とどの要素が仲間なのかが分かりません。
読む人は上から順に、同じ重さで全部を読むことになります。

after では距離を3種類に分けました。

.eyebrow { margin-bottom: 18px; }  /* 見出しと近い。セットで読ませる */
h1       { margin-bottom: 22px; }  /* リード文と近い */
.lead    { margin-bottom: 40px; }  /* ここで大きく開ける */

やっていることは1つです。関係が強いものを近づけ、弱いものを離す。

数字そのものに意味はありません。差があることに意味があります。

手2: 中央寄せをやめて、左端を1本に揃える

次に見るのは、視線の入口です。

AI はほぼ確実に中央寄せを選びます。指定しなければ text-align: center が付きます。

中央寄せが選ばれるのは、それが無難だからです。
要素の幅がまちまちでも、中央に置けば形になります。

ただし中央寄せは、行の長さが変わるたびに文の始まりの位置が動きます。

読む人の目は、1行読むごとに左端を探し直すことになります。

/* before */
.hero { text-align: center; max-width: 800px; }

/* after: 左右2カラムにして、テキストの左端を1本に固定する */
.hero {
  display: grid;
  grid-template-columns: minmax(0, 1fr) auto;
  gap: 56px;
  align-items: center;
}
.lead { max-width: 30em; }

text-align を消し、リード文に max-width: 30em を掛けています。

横に長い行は、目が戻るときに行を見失います。

同じ手のなかで、要素も削りました。

<!-- before: 特徴を3つ並べていた -->
<div class="points">
  <div class="point">✨ かんたん導入</div>
  <div class="point">⚡ 高速処理</div>
  <div class="point">🔒 安心のセキュリティ</div>
</div>

<!-- after: 丸ごと削除 -->

ファーストビューで読ませるものは1つに絞ります。

3つ並べると、読む人はどれが主役か判断できません。判断できないものは読み飛ばされます。

手3: 色数を絞って、アクセントを1箇所にする

before では色が5系統ありました。

  • 背景のグラデーション（青紫〜紫）
  • 見出しの白と影
  • バッジの半透明の白
  • ボタンのグラデーション（黄〜オレンジ）
  • 特徴パネルの半透明の白

after では、色を主題から決め直しました。

/* before: 意味のないグラデーション */
body { background: linear-gradient(135deg, #667eea 0%, #764ba2 100%); }
.cta { background: linear-gradient(90deg, #f6d365 0%, #fda085 100%);
       box-shadow: 0 10px 30px rgba(0, 0, 0, 0.3); }

/* after: 夜の作業画面と、熱として消えていく時間 */
:root {
  --bg:      #12111b;   /* 夜の作業画面 */
  --surface: #1c1b28;
  --line:    #2e2b40;
  --fg:      #edebf4;
  --fg-2:    #918da8;
  --amber:   #ffb43d;   /* 定型作業に消えている5分 */
  --amber-d: #b87516;   /* ブロックの側面。厚みを作る */
}

紫を別の色に置き換えたのではありません。

扱っている題材から色を持ってきています。

この製品が扱うのは「作業時間が少しずつ消えていくこと」です。
だから背景は夜の作業画面、消えていく時間は熱を持った琥珀にしました。

「落ち着いた色にする」と考えると、どのサイトも同じ薄いグレーになります。
「この製品は何の世界の話か」から決めると、色に理由が生まれます。

グラデーションを全部やめたわけではありません。1箇所だけ残しています。

/* 画面の隅にだけ光を置く。全面グラデーションにはしない */
body::before {
  content: "";
  position: fixed;
  top: -20%; right: -10%;
  width: 60vw; height: 60vw;
  background: radial-gradient(circle, rgba(255,180,61,.10) 0%, transparent 62%);
  pointer-events: none;
}

全面に敷くと、どこを見ればいいのか分からなくなります。
隅に置くと、視線が向かう先だけが明るくなります。

手4: 削った余力を、1箇所に集中させる

ここまでが引き算です。引き算だけで終えると、整った代わりに退屈になります。

削って空いたぶんを、1箇所にだけ投下します。

作例では、右側の立体ブロックがそれです。

1ブロックが5分。週5日 × 1日3ブロックで15個。それが1つずつ抜けていきます。

まず、面を寝かせて立体にします。画像もライブラリも使いません。

.stage { perspective: 1000px; }

.deck {
  display: grid;
  grid-template-columns: repeat(5, 40px);
  gap: 12px;
  padding: 26px;
  background: var(--surface);
  border: 1px solid var(--line);
  border-radius: 10px;
  transform: rotateX(52deg) rotateZ(-40deg);
  transform-style: preserve-3d;
}

rotateX で手前に倒し、rotateZ で回します。この2行だけで机の上の面になります。

ブロックの厚みは、影を重ねて作ります。

.block {
  width: 40px; height: 40px;
  background: var(--amber);
  border-radius: 3px;
  /* 側面の影を段階的に積むと、平面が箱に見える */
  box-shadow:
    2px 2px 0 var(--amber-d),
    4px 4px 0 var(--amber-d),
    6px 6px 0 var(--amber-d),
    8px 8px 14px rgba(0, 0, 0, .45);
}

同じ方向に少しずつずらした影を4枚重ねているだけです。

最後に、消えていく動きを付けます。

.block {
  animation: drain 7s cubic-bezier(.4, 0, .2, 1) infinite;
  animation-delay: calc(var(--i) * .18s);
}

@keyframes drain {
  0%, 58%   { opacity: 1;   transform: translateZ(0); }
  76%, 88%  { opacity: .18; transform: translateZ(-16px); }
  100%      { opacity: 1;   transform: translateZ(0); }
}
<span class="block" style="--i:0"></span>
<span class="block" style="--i:1"></span>

--i を HTML 側で渡して、animation-delay をずらしています。
15個ぶんの CSS を書かずに、順番に抜けていく動きが作れます。

キーフレームの配分に注意してください。

最初は「消えている時間」を長く取っていました。すると画面を開いた瞬間、
ほとんどのブロックが暗い状態で目に入ります。

0%, 58% を「見えている」に割り当てて、消えるのは一瞬にしました。
アニメーションは、止まっているときの見た目のほうが長く目に触れます。

動きを止める設定も尊重します。

@media (prefers-reduced-motion: reduce) {
  .block { animation: none; }
}

止めても意味が伝わる形にしてあります。動きは補助であって、情報そのものではありません。

なぜ数字を大きく置かなかったか

「週75分」と書けば1行で済みます。

そうしなかったのは、大きい数字と小さいラベルの組み合わせが、
どのLPにもあるからです。AI に「目を引く要素を作って」と頼むと、まずこれが出ます。

ブロックにすると、読む人は数えます。 数えた時点で、
自分の1週間に置き換えて考えています。

目を引く要素は1つでいい。 2つ置くと、どちらも弱くなります。

実際に投げたプロンプト

after を作るときに使った指示の全文です。

このファーストビューを直してください。手順を分けます。

■ 削る（1〜3）

1. 余白の緩急
   要素間のマージンが全部 20px で均一です。
   関係が強い要素どうしは近づけ（18〜22px）、
   意味の切れ目では大きく開けて（40px以上）ください。

2. 視線の入口
   text-align: center をやめ、左右2カラムの grid にしてください。
   テキストの左端を1本に固定します。
   リード文には max-width: 30em を掛けて1行を短くします。
   ファーストビューで読ませる要素を1つに絞るため、
   特徴を3つ並べたブロックは削除してください。

3. 色
   全面グラデーションと text-shadow をやめてください。
   そのうえで、色を「落ち着いた色」から選ばないでください。
   この製品が扱う題材は「作業時間が少しずつ消えていくこと」です。
   その主題から背景とアクセントを決め、CSS 変数で定義してください。
   光を使う場合は画面の隅に1箇所だけ置き、全面には敷かないでください。

■ 足す（4）

4. 目を引く要素を1つだけ作る
   削って空いた領域に、この製品の主題を一目で伝える要素を置きます。
   条件は4つです。
   - 大きな数字とラベルの組み合わせにしない（どのLPにもあるため）
   - 読む人が数えたり目で追ったりできる形にする
   - 外部ライブラリを使わず、CSS の transform と box-shadow だけで作る
   - 手3で決めた色の世界と地続きにする

   1ブロック5分の立体を週5日 × 3個で並べ、
   perspective と rotateX / rotateZ で寝かせてください。
   厚みは同方向にずらした box-shadow を重ねて作ります。

   ブロックが1つずつ抜けていくアニメーションを付けます。
   animation-delay は HTML 側の --i 変数からずらしてください。
   キーフレームは「見えている時間」を6割以上に配分します。
   prefers-reduced-motion では動きを止めてください。

変更した箇所には、どの手に対応するかをコメントで残してください。

指示を4つに区切っているのは、どこを直したか後から確認するためです。

「もっとおしゃれにして」と頼むと、AI は全部を作り直します。
そうなると、良くなったのか悪くなったのかを比べられません。

手4だけは、条件を4つ書いています。

ここを曖昧にすると、AI は大きな数字とグラデーションのカードを出します。
避けたい形を名指しで書くほうが早いです。

「外部ライブラリを使わない」と書いているのは、
放っておくと Three.js を持ち出してくるからです。

立体を作るだけなら transform と box-shadow で足ります。
読み込むものが増えると、記事を読んだ人が自分の画面に持ち帰れなくなります。

つまずきどころ

3つあります。

1つ目は、引き算で止めてしまうことです。

色を減らし影を消した時点で、画面は「整って」見えます。

そこで手を止めると、読みやすいけれど印象に残らない画面になります。
削るのは、足すための準備です。

2つ目は、目を引く要素を2つ以上置くことです。

格子を作ったあと、ボタンにもアニメーションを付けたくなります。

2つ置くと視線が割れて、どちらも弱くなります。

3つ目は、数値をそのまま真似することです。

この記事の 18px / 22px / 40px は、この作例で決めた値です。

覚えるのは数字ではなく、3種類に分けるという考え方のほうです。

今日できること

手元の画面のマージンを、grep で数えてみてください。

grep -o "margin-bottom: [0-9]*px" your-styles.css | sort | uniq -c

同じ値が5個以上並んでいたら、余白に緩急がありません。

そこが最初に直す場所です。

ただし、そこで止めないでください。

削ったあとに何を1つ足すかで、印象に残るかどうかが決まります。
