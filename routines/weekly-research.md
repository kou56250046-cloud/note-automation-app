# weekly-research

1週間分のテーマを仕込む Routine。**これが毎日投稿を成立させている。**

| 項目 | 設定 |
|---|---|
| cron | `0 7 * * 1`（月曜 07:00 JST） |
| モデル | Sonnet 5 |
| effort | high |
| 消費 | 1/週 |

日次の記事生成は web 検索をしない。ここで作った在庫から引くだけである。

リサーチを日次で回すと月2,000円相当かかる。週次に集約すると月250円になり、
**削減した1,750円がそのまま記事26本分の原資になる。**

---

## プロンプト（Routines に登録する本文）

```
このリポジトリの1週間分のネタ在庫を補充してください。

まず CLAUDE.md を読み、そこに書かれたルールをすべて守ってください。
特に以下は絶対です。

- knowledge/account.md のカテゴリ範囲外のテーマは在庫に入れない
- 範囲外のテーマは捨てずに learnings.md に理由付きで記録する
- 出典のないテーマを在庫に入れない
- 選定理由（次点と、それを落とした理由を含む）を必ず残す

## 手順

1. knowledge/account.md を読み、主カテゴリとサブカテゴリを確認する。
   存在しなければ停止し、/note-init の実行を促す。

2. 現在の在庫を数える。research/themes.md の status: pending の本数。

   7本を無条件に足さないでください。「7本になるまで補充」します。
   残数が7本以上なら、補充せず曜日の割り当てだけ見直して終了します。

3. knowledge/learnings.md を読み、過去に却下したテーマを把握する。
   同じものを拾い直さないでください。

4. notes/*/meta.json を読み、既出記事のタイトルを把握する。

5. researcher サブエージェントで調査する。
   - サブカテゴリごとに、読者が繰り返し困っていることを探す
   - 公式ドキュメントの更新や仕様変更を確認する
   - research/accounts/{genre}.md の空白地帯を参照する
   - 検索は15件程度で切り上げる。それ以上調べても選ぶテーマは変わらない
   - 検索結果の全文を返さず、要約と出典だけを返す

6. スコアリングする。3軸で各5点。根拠を必ず添える。
   - 強み: account.md の主カテゴリど真ん中か。手元の材料だけで書けるか
   - 市場性: 検索されているか。競合が答えていないか
   - 支払い意欲: 解決に金を払う痛みがあるか。手順を丸ごと渡せる形か

7. カテゴリ範囲外を除外する。
   スコアが高くても account.md の範囲外なら在庫に入れません。
   learnings.md の「範囲外として在庫に入れなかったテーマ」に
   日付・テーマ・スコア・却下理由を追記してください。

8. 曜日と type を割り当てる。
   月火水金土 = free / 木日 = paid

   type: paid には支払い意欲4以上のテーマだけを割り当てます。
   該当が足りなければ paid を減らし、その旨を報告してください。

   同じサブカテゴリを連続させないでください。週の中で散らします。

9. research/themes.md に追記する。既存の pending を消さないでください。
   各エントリに以下を必ず書きます。
   - id / title / type / day / category
   - score（strength / market / willingness / total）
   - rationale（次点と、それを落とした理由を含む）
   - angle（既出記事との差別化点）
   - sources（出典URL）
   - status: pending
   - type: paid のときは execution: local と productTypeHint: tool も書く

   profile.md が空のうちは productTypeHint に tool 以外を書かないでください。
   体験談型は実績が必須で、sales-letter が停止します。

10. git add / commit / push する。

## 報告

- 補充した本数（既存の pending → 合計）
- 曜日ごとのテーマ一覧とスコア
- 範囲外として除外したテーマと理由
- 次点（在庫に入れなかったが有望なもの）
- 支払い意欲4以上が足りずに paid を減らした場合はその旨
```

## 在庫が切れると止まる

**毎日投稿の唯一の停止要因は在庫の枯渇である。**

`stock-alert` Actions が毎朝チェックし、`pending` が3本未満なら Issue を立てる。
Issue が立ったら、次の月曜を待たずにこの Routine を手動実行する。

Pro プランの予備2枠はこのためにある。
