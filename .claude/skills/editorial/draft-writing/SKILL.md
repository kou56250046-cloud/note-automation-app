# draft-writing

**買った人が手元で動かせる状態にする。** それがこのスキルの全てである。

---

## `writer` サブエージェントで実行する

執筆に集中させ、判定させない。出来の良し悪しは `critic` と `auditor` が判断する。

---

## ローカル実行のみ

**`03-draft.md` は `.gitignore` 対象である。** public リポジトリに置けば
誰でも読めて商品価値が消えるため追跡していない。

クラウドで動くものはコミットして完了するため、そこで生成すると手元に残らない。
**クラウドで実行しない。**

---

## 入力

| ファイル | 必須 | 何に使うか |
|---|:---:|---|
| `notes/{slug}/00-concept.md` | ○ | `productType` / 渡すもの / 構成 |
| `notes/{slug}/pricing.json` | ○ | **天井**。約束の範囲を超えて書かない |
| `notes/{slug}/02-letter.md` | ○ | レターで約束したこと。**ここと矛盾させない** |
| `knowledge/account.md` | ○ | ペルソナ |
| `knowledge/profile.md` | ○ | **書けないこと** |
| `knowledge/voice.md` | ○ | 文体・禁止表現 |

1つでも欠けたら**停止して不足ファイル名を報告する。** 推測で埋めない。

**`02-letter.md` を必ず読む。** レターで約束したものが本文に無いと、
それは返金対象の不備であって文章の問題ではない。

---

## 道具型（`productType: tool`）で必ず書く4つ

**この4つが揃わない原稿は完成していない。**

| 項目 | なぜ必要か | 書き方 |
|---|---|---|
| **成果物の中身** | **これが再現性の根拠そのもの。** 出し惜しみすると商品にならない | コード・テンプレート・プロンプトを**全文**。断片や要約にしない |
| **動作条件** | 無いと「動かない」というクレームになる | 何のバージョンで、何が必要で、何を許可するか |
| **最初の1歩** | 買った直後の離脱を防ぐ | 「まずこれをコピーする」の1手 |
| **できないこと** | 適用範囲の外。書かないと信用を失う | 「これは扱わない」を具体的に |

### 出し惜しみをしない

```
✕ 「テンプレートは全部で12個あります。以下がその一覧です」＋目次だけ
○ 12個すべてを本文にそのまま貼る
```

**目次は成果物ではない。** 買った人が読むのは中身である。

---

## 抽象論を書かない

**有料部分で最も価値が落ちるのは、無料記事で読める話が入ることである。**

| ✕ 書かない | ○ 代わりに |
|---|---|
| 「デザインでは余白が重要です」 | `padding: 40px 28px` にした理由と、変える前の値 |
| 「プロンプトは具体的に書きましょう」 | 実際のプロンプト全文と、曖昧版との出力差 |
| 「エラーが出たら確認しましょう」 | そのエラーメッセージと、そのときの対処コマンド |

**一般論は無料部分（レター）に置く。有料部分には実物を置く。**

---

## 天井を超えない

`pricing.json` の `ceiling` が約束の範囲である。

```
天井: 「テンプレ丸出しに見える3箇所を直せるところまで」
  ↓
✕ 「これでデザイナーと同じ判断ができます」   → 天井を超えた。E2 に当たる
○ 「この3箇所以外は扱いません」               → 範囲を守った
```

**超えた瞬間に `ethics-line` の E2（盛った恐怖・過剰な約束）が立つ。**

---

## 構成

`00-concept.md` の「有料部分」の見出しに従う。**勝手に変えない。**

分量は **5000〜8000字**。ただしコードとテンプレートの全文は字数に数えない。
**実物が長いことは問題ではない。説明が長いことが問題である。**

```
1. これから渡すものの全体像   何が何個あるか。地図を先に見せる
2. 動作条件                   ここでつまずくと全部止まる。先に書く
3. 最初の1歩                  1手だけ。ここで動くことを確認させる
4. 成果物（本体）             全文。ここが商品
5. つまずきどころ             実際に引っかかる箇所と対処
6. できないこと               適用範囲の外
```

**2 と 3 を後ろに置かない。** 動かない状態で本体を読ませると離脱する。

---

## 書いてはいけないこと

**`profile.md` の「書けないこと」を必ず読む。** 言い換えても書かない。

| ✕ | ○ 代わりに |
|---|---|
| 「これで月◯万円になります」 | 手順そのものの説明 |
| 「◯人が使っています」 | 何ができるかの説明 |
| 「作業時間が◯%減ります」 | どの作業が不要になるかの説明 |
| 「必ず」「絶対に」「誰でも」 | 条件を明示する（`voice.md` の `ng`） |

`profile.md` の実績を引用するときは**前提を必ず添える。**
前提を落とした引用は `ethics-line` の E3 に当たる。

**足りないものを埋めるために創作しない。** 書かずに `report.md` に記録する。

---

## note で崩れる記法を使わない

有料部分も note に貼るため、制約は無料記事と同じである。

| 記法 | 可否 |
|---|---|
| 見出し（H2 / H3）・太字・引用・水平線 | ○ |
| 箇条書き（2階層まで） | ○ |
| コードブロック | ○（言語指定は貼付後に手動で設定する） |
| **テーブル** | **✕ note が非対応。箇条書きにする** |
| 脚注・3階層以上のリスト | ✕ |

`scripts/lint.py` が `03-draft.md` も検査する。

本文のみ。**タイトルは含めない**（`title-design` の担当）。

**このファイルは追跡されない。** ローカルにのみ存在する。

## 物差し（これを満たさなければ渡さない）

**自己評価ではない。構造的な充足の確認である。**

| # | 条件 | 満たさないとき |
|---|---|---|
| 1 | 成果物が**全文**入っている（目次や要約でない） | 全文を書く |
| 2 | 動作条件が書かれている | 書く。無いとクレームになる |
| 3 | 最初の1歩が1手で書かれている | 1手に絞る |
| 4 | できないことが書かれている | 書く |
| 5 | `02-letter.md` で約束したものが全て入っている | 入れる。無いのは不備である |
| 6 | `pricing.json` の天井を超えていない | 超えた記述を削る |
| 7 | 抽象論だけの節が無い | 実物に置き換える |
| 8 | `profile.md` に無い実績を書いていない | 削る |

**1〜4 は道具型の必須要件である。** どれか1つでも欠けたら、
`letter-audit` の C2（再現性）が落ちる。

---

## 書き終えたら

**自己評価しない。** そのまま次に渡す。

```
1. scripts/lint.py で 03-draft.md を検査      ← トークン0
2. letter-audit（critic / Opus 5）最大2周      ← レターと本文を通しで見る
3. ethics-line（auditor / full）上限なし       ← 有料は必ず実行する
4. title-design（8案）
5. build-report
```

**有料noteでは `ethics-line` を必ず実行する。** 無料記事のような
「検出時のみ」の分岐は適用しない。売る以上、景品表示法・特定商取引法の
リスクが実在する。

「良い出来かどうか」を自分で結論しない。それは `critic` と `auditor` の仕事である。
