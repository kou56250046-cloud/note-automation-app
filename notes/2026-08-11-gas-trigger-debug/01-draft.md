GASのトリガーが動かないとき、原因はだいたい3箇所に絞れます。

①トリガーが実際に設定されているか。
②スコープの承認が通っているか。
③実行ログにエラーが残っているか。

この順番で見ていくと、原因の切り分けが早くなります。
今日はこの3箇所を、確認用のコードつきで見ていきます。

---

## 「動いているはず」なのに動かない

GASの時間主導トリガーは、設定したその場では確認できません。
翌朝になって「動いていなかった」と気づく形になりがちです。

よくある症状はこの3つです。

- トリガーを設定したつもりが、次の日になっても実行された形跡がない
- 実行はされているようだが、シートやドキュメントに変化がない
- エラーも出ず、実行数のログにも何も残っていない

厄介なのは、エラーメッセージが出ないパターンです。
スクリプトエディタで手動実行したときは動くのに、
トリガー経由だと黙って止まる。原因がコードの中にないので、
コードを何度読み直しても見つかりません。

こういうときは、コードを疑う前に、コードの外側を疑ったほうが早いです。
トリガー・権限・ログの3箇所は、コードとは別の場所にある設定だからです。

---

## 上から順に見る3箇所

### ①トリガーが実際に設定されているか

まず疑うべきは「設定したつもりで、設定できていない」状態です。

GASのエディタ画面には、時計のアイコンの「トリガー」というメニューがあります。
ここを開いて、対象の関数名と実行間隔が意図した通りになっているかを確認します。

ありがちな失敗は次の2つです。

- 関数名を後から変更して、トリガーの参照先が古い関数名のまま残っている
- 同じ関数に対して、以前作ったトリガーが重複して残っている

**トリガーの参照は、関数を消したり名前を変えたりしても自動更新されません。**
関数名を変えたら、トリガーも手動で作り直す必要があります。

一覧画面を目視するだけでも分かりますが、
数が増えてくると見落とすので、コードで確認する方法を後半で載せます。

### ②スコープの承認が通っているか

トリガーが正しく設定されていても、動かないことがあります。
次に見るのは、承認したはずの権限が実は通っていないケースです。

GASは、外部URLへの接続やドキュメントの編集など、
コードが使う機能ごとに承認（スコープの許可）を求めます。

この承認は、手動実行のときに一度だけ求められます。
承認済みなら、以後は自動で使われるはずです。

ただし、次のような操作をすると、承認がリセットされることがあります。

- コードに新しい機能（新しいAPIの呼び出し）を追加した
- スクリプトを複製して、別のGoogleアカウントで開いた
- `appsscript.json` の `oauthScopes` を手動で書き換えた

リセットされた状態でトリガーが動くと、
承認ダイアログを出す相手がいないため、エラーとして処理されるか、
何もせず処理が止まります。**トリガー経由の実行では、承認ダイアログは出ません。**
これが「手動なら動くのに自動だと動かない」の典型パターンです。

対処は単純で、スクリプトエディタから対象の関数を1回手動実行し、
承認画面が出ないかを確認するだけです。出た場合は、それが原因です。

### ③実行ログにエラーが残っているか

トリガーも設定されている、承認も通っている。
それでも動かないなら、最後に見るのはログです。

GASには2種類のログがあります。

- 実行数（Executions）画面 — 関数ごとの実行結果と所要時間の一覧
- `Logger.log()` の出力 — 手動実行時に「実行ログ」として確認できる

トリガー経由の実行では、`Logger.log()` の出力はその場に表示されません。
確認できるのは「実行数」画面のほうです。

エディタの左メニューにある「実行数」を開くと、
関数名・開始時刻・所要時間・ステータス（完了/失敗）が並びます。

**失敗している行をクリックすると、例外メッセージとスタックトレースが出ます。**
ここに原因がそのまま書かれていることがほとんどです。

「実行数に何も残っていない」場合は、①に戻ります。
そもそもトリガーが発火していない可能性が高いからです。

## 確認用のコードと設定

言葉だけで追うと分かりにくいので、確認用の短いコードを用意しました。
そのままスクリプトエディタに貼って使えます。

```javascript
/**
 * 現在設定されているトリガーを一覧でログに出す。
 * スクリプトエディタで、この関数を選んで実行してください。
 */
function checkTriggers() {
  const triggers = ScriptApp.getProjectTriggers();

  if (triggers.length === 0) {
    Logger.log('トリガーが1つも設定されていません。');
    return;
  }

  triggers.forEach(function (trigger) {
    Logger.log(
      '関数名: ' + trigger.getHandlerFunction() +
      ' / イベント種別: ' + trigger.getEventType() +
      ' / トリガー種別: ' + trigger.getTriggerSource()
    );
  });
}

/**
 * トリガーから呼ばれる想定の関数。
 * 実行されると「実行数」画面に必ず1行残る。
 */
function myTriggeredFunction() {
  const now = new Date();
  Logger.log('myTriggeredFunction が実行されました: ' + now);
}
```

`checkTriggers` は、参照している関数名がすでに存在しない関数名でも、
エラーを出さずにそのまま表示します。
一覧を見て、想定した関数名と一致しているかを目で確認してください。

`myTriggeredFunction` は中身をほぼ空にしてあります。
これをトリガーに登録して1日待ち、「実行数」画面に行が増えていれば、
トリガー自体は正しく発火していると判断できます。

### appsscript.jsonのスコープ記述

権限まわりを目視で確認したいときは、`appsscript.json` を開きます。
スクリプトエディタの左メニューにある歯車から「マニフェスト」を表示すると開けます。

```json
{
  "timeZone": "Asia/Tokyo",
  "dependencies": {},
  "exceptionLogging": "STACKDRIVER",
  "oauthScopes": [
    "https://www.googleapis.com/auth/documents",
    "https://www.googleapis.com/auth/script.external_request",
    "https://www.googleapis.com/auth/script.scriptapp"
  ],
  "runtimeVersion": "V8"
}
```

`oauthScopes` に列挙されている項目が、コードが実際に使っている機能と
一致しているかを確認します。

たとえば外部APIを呼んでいるのに `script.external_request` が無い場合、
コードを書き換えた直後で承認が更新されていない可能性があります。

### トリガーの設定手順

登録済みのつもりでも、意図しない条件になっていることがあります。
手順ごと確認してください。

1. スクリプトエディタ左メニューの時計アイコン（トリガー）を開く
2. 「トリガーを追加」を押す
3. 実行する関数（`myTriggeredFunction` など）を選ぶ
4. イベントのソースで「時間主導型」を選ぶ
5. 時間ベースのタイマー種別（毎日・毎時など）と、実行する時間帯を選ぶ
6. 保存を押す

保存後、一覧に戻って行が増えているかを必ず確認してください。
保存ボタンの反応が薄く、押せていないまま画面を閉じることがあります。

### 実行ログの読み方

「実行数」画面には、次の列が並びます。

- 関数 — どの関数が実行されたか
- 開始 — 実行された日時
- 期間 — 実行にかかった時間
- ステータス — 完了 / 失敗 / タイムアウトなど

**ステータスが「失敗」の行をクリックすると詳細が開きます。**
そこにエラーメッセージとスタックトレースが表示されます。

「トリガーが設定されているのに実行数に何も出ない」場合は、
トリガーが発火する前の段階、つまり①の問題である可能性が高いです。

## つまずきやすいところ

**6分の実行時間制限に、黙って引っかかる**

GASの1回の実行には時間の上限があります。
無料アカウントでは6分が上限です。

処理が長くかかるコード（大量のデータ処理やAPI呼び出しの連続）は、
上限に達した瞬間に強制終了します。

このとき、エラーメッセージが分かりやすく出ないことがあります。
「実行数」でステータスを見ると「失敗」と出ているだけで、
理由の記述が薄いことがあるので、まず処理時間を疑ってください。

対処法は、処理を分割して複数回のトリガーに分ける方法です。
1回の実行で扱うデータ量を減らすだけでも改善します。

**トリガー経由では`alert`が使えない**

`DocumentApp.getUi().alert()` のような、UIにダイアログを出す命令は、
手動実行では動きますが、トリガー経由の実行では使えません。

画面を持たない自動実行の中でUI操作を呼ぶと、
そこで例外が発生して処理が止まります。

トリガーで動かす関数の中に `alert` や `prompt` が残っていないか、
確認しておくと防げます。

上の `checkTriggers` を、今使っているスクリプトエディタに貼ってください。

実行すると、今そのプロジェクトに設定されているトリガーが、
関数名・イベント種別・トリガー種別つきで一覧に出ます。

想定していた関数名と違うものが登録されていないか、
このタイミングで確認してみてください。

それだけで、①の切り分けは終わります。
