以下の条件で16:9の画像を1枚作ってください。

## 被写体（最重要）
生成り色の紙のテーブルの上に、薄いカード状のパネルが置かれている。
・左側: 同じ大きさの正方形パネルが4枚、均等な間隔で整然と並んでいる。すべて同じ高さに浮いている
・右側: 1枚のパネルだけが他より一回り大きく、わずかに高く持ち上がっている。残り3枚は小さく低い位置に並ぶ
どちらの面にも実際の文字やUIラベル、グラフは描き込まない。大きさと配置の対比だけで見せる。

## 構図
・左に「均一な4枚」、右に「1枚が主役の配置」を置き、視線が左から右へ流れる構図
・右側の主役パネルの奥、画面右端の2割を平坦な余白として空ける
・浅い被写界深度。手前のパネルにピントを合わせ、奥はわずかにぼかす

## 色
・背景の基調: #f6f3ec（生成りの紙）
・インク: #221f19。パネルの縁や影に使う
・アクセント: #2456e0（藍）。右側の主役パネルの縁にのみ使う。1色だけ
・コントラストを強く。中間色を多用しない

## 質感とライティング
・Appleの製品ページのようなプロダクト写真
・斜め上からの単一光源。影の方向をすべて揃える
・紙とパネルの質感、薄い影の落ち方を丁寧に描写する
・高精細、ノイズなし、4K品質

## テキスト(必須・大きく主張する)
右上の余白に「3箇所だけ直す」というキーワードを大きく配置してください。

・太い書体（Bold/Black相当）で、パネルと同じかそれ以上の視覚的な強さで配置する
・文字色は #2456e0（藍）で統一し、#f6f3ec の背景とのコントラストを最優先する
・文字の縁取りや薄いドロップシャドウで可読性を確保する。背景に溶け込ませない
・デザイン性を最優先する。ただの文字の貼り付けではなく、パネルの配置と一体化した
  タイポグラフィとして配置する

## 避けるもの
・グラデーションを全面に敷くこと
・複数の光源で影の方向がばらつくこと
・要素を5つ以上並べること
・脳のイラスト、光る回路基板、ロボットの手、青い網目状のネットワーク
・ノートPCの前に座る人物
・パネルに実際の文字やUIラベル、グラフを描き込むこと
・キーワードが背景に埋もれて読みにくくなること

AIに管理画面を作らせると、その場で動く画面が出てきます。

サイドバーがあり、KPIカードが並び、テーブルもあります。

それでも、そのままではチームに見せられません。

直す場所は3つだけです。余白、階層、色数です。

この3つを順番に直すと、同じ情報量のまま印象が変わります。

コードもデザインの知識も、大きく増やす必要はありません。

「動くけど見せられない」の中身

指示はたいてい「管理画面を作って」の一言だけです。

それでもサイドバーもKPIカードもテーブルも、ひととおり出てきます。崩れてもいません。

共有する前にスクリーンショットを撮って、結局送らなかった人もいるはずです。

これは怠慢ではありません。指示に強弱の情報が含まれていないだけです。

AIは、頼まれた要素をすべて同じ重みで置こうとします。どれが主役かの判断は、指示した側の役目です。

これは管理画面に限った話ではありません。LPでもチャット画面でも同じことが起きます。

売上のカードも、返品率のカードも、同じ大きさ、同じ太さの文字で並びます。

余白も全部同じ値です。テーブルの見出しだけ派手な青で塗られています。

読む人は、どこを最初に見ればいいのか分かりません。

作例を用意しました。左がAIの出力そのまま、右が直したものです。

作例では、サイドバー・KPI・注文一覧という同じ3ブロックを、直す前後で並べています。

https://kou56250046-cloud.github.io/note-automation-app/demo/2026-08-11-ui-3points/

同じ項目を使っています。並び順もほぼ同じです。

違うのは、余白の付け方、要素の強弱、そして色の数です。

手1: 余白を均一に置かない

before のCSSは、どの要素も margin-bottom が同じ値でした。

/* before */
.kpi { padding: 16px; margin-bottom: 16px; }
.panel { padding: 16px; margin-bottom: 16px; }
th, td { padding: 16px; }

余白が全部16pxだと、セクションの切れ目と、要素どうしの近さが区別できません。

余白は、判断が要らないところから直せる部分でもあります。マージンの値は数えれば分かります。

after では、意味の切れ目で大きく空け、関係が強いところは詰めました。

/* after */
.main { padding: 40px 48px; }
.kpis { gap: 20px; margin-bottom: 40px; }
.kpi-sub-list { gap: 14px; padding: 20px 24px; }
.panel { padding: 24px 28px; }

KPIのブロックとテーブルの間は40px空け、KPI内部の項目どうしは14pxに詰めています。

この作例では14〜20pxを近い関係に、40pxを意味の切れ目に使っています。

数字そのものより、値に差があることが効いています。

LPと違い、管理画面は毎日同じ人が見る画面です。だからこそ、迷わず同じ場所を見られる状態を保つ必要があります。

手2: 情報の強弱をはっきりさせる

before では、4枚のKPIカードがすべて同じ大きさ、同じ太さの文字でした。

売上も返品率も、画面上の重みが同じです。

/* before: 全カードが同じ扱い */
.kpi .label { font-size: 16px; font-weight: 700; }
.kpi .value { font-size: 16px; font-weight: 700; }

管理画面を毎日開く人が最初に見るのは、たいてい1つの数字です。

主役の選び方に迷ったら、その画面を毎日見る人が最初に確認する数字を選んでください。多くの場合、それは売上か件数のどちらかです。

今回は「今月の売上」をそれに決め、1枚だけを大きくしました。

/* after: 主役は1枚だけ大きくする */
.kpi-hero .value { font-size: 36px; font-weight: 700; color: var(--accent); }
.kpi-sub .value  { font-size: 15px; font-weight: 600; }
.kpi-sub .delta  { font-size: 11px; color: var(--ink-2); }

残り3項目は、値だけ確認できればいい情報として、小さいリストに下げています。

残りの項目は、数値だけを一列に並べる形にしています。デザインの主張を持たせず、確認用の情報として扱っています。

全部を見せるのではなく、順番をつけるのが階層です。

手3: 色数を絞って、アクセントを1箇所にする

before では、KPIカードに4色のグラデーションを個別に使っていました。

/* before: カードごとに違う色を割り当てている */
.kpi.c1 { background: linear-gradient(135deg, #ff5f6d 0%, #ffc371 100%); }
.kpi.c2 { background: linear-gradient(135deg, #11998e 0%, #38ef7d 100%); }
.kpi.c3 { background: linear-gradient(135deg, #8e2de2 0%, #4a00e0 100%); }
.kpi.c4 { background: linear-gradient(135deg, #f7971e 0%, #ffd200 100%); }

赤、緑、紫、オレンジ。意味の割り当てはなく、順番に色を回しているだけです。

after では、色をCSS変数にまとめ、藍色1色だけをアクセントにしました。

/* after: アクセントは1色。他はインクとグレーだけ */
:root {
  --paper:  #f6f3ec;
  --ink:    #221f19;
  --ink-2:  #85796a;
  --accent: #2456e0;
}
.kpi-hero .value { color: var(--accent); }
.spark span { background: var(--accent); }

背景を白ではなく生成りにしたのは、管理画面でも人の手が入っている印象を残すためです。

アクセントを1色にすると、色を見ただけで「ここが主役だ」と分かります。

状態を示す緑や赤は残しましたが、彩度を落として文字とドットだけにしています。

浮いた分は、売上の推移を示す7本の棒グラフに使いました。画像もライブラリも使っていません。

.spark { display: flex; align-items: flex-end; gap: 6px; height: 56px; }
.spark span { width: 10px; border-radius: 2px 2px 0 0; background: var(--accent); }

棒の高さは、直近7日の売上を単純に正規化しただけです。複雑な計算は要りません。

最終的に使っている色は、生成り・インク・グレー・藍の4色だけです。

高さは style="height:34%" のようにインラインで渡すだけです。7本並べれば推移に見えます。

実際に投げたプロンプト

after を作るときに使った指示の全文です。

この管理画面を直してください。手順を分けます。

1. 余白
   padding と margin-bottom が全部16pxで統一されています。
   セクションの切れ目(KPIとテーブルの間など)は40px前後まで開け、
   同じブロック内の項目どうしは12〜14pxまで詰めてください。

2. 情報の階層
   4枚のKPIカードが同じ大きさ、同じ太さで並んでいます。
   このうち「今月の売上」を主役に決め、
   数値を36px程度まで大きくして色を付けてください。
   残り3項目は値だけ分かればいい補助情報として、
   小さいリスト形式に下げてください。

3. 色数
   KPIカードに赤・緑・紫・オレンジの4色を個別に使っています。
   意味のない色分けなので、CSS変数にまとめて
   アクセントカラーを1色だけ選んでください。
   他の要素は背景色(生成り)と文字色(濃いインク色、薄いグレー)の
   2階調に絞ってください。
   ステータス表示のような意味を持つ色分けだけは残してよいですが、
   彩度を落として小さく使ってください。

4. 空いた領域の使い道
   色数を絞って空いた分は、主役カードの中に
   直近7日間の推移を示す棒グラフとして使ってください。
   画像やグラフ用のライブラリは使わず、
   高さの異なる div を並べるだけで作ってください。

変更した箇所には、どの手に対応するかをコメントで残してください。

3つの指示を番号で分けているのは、直した結果を後から数えられるようにするためです。

「見やすくして」だけでは、AIはKPIカードの色をやや薄くする程度で止まります。

避けたい配色を先に書いているのは、放っておくとブラウザ標準の青やAIの既定色がそのまま残るからです。

どの要素を主役にするかを、こちらで先に決める必要があります。

つまずきどころ

3つあります。

1つ目は、色を減らすだけで満足してしまうことです。

彩度を落として終えると、画面は静かになりますが、どこを見ればいいかは変わりません。

色を減らすのは、1箇所に色を集めるための準備です。

2つ目は、主役を複数選んでしまうことです。

「売上も注文数も大事だから両方大きく」とすると、結局before と同じ状態に戻ります。

主役は1つに絞ります。

3つ目は、アクセントカラーを選ばずに、既定の青のまま使うことです。

指定しないと、ブラウザやAIが選んだ青がそのまま残ります。

自分の題材から1色を選び直してください。

3つとも、直す前に一度だけ確認すれば防げます。確認の順番は、色、階層、主役の1色を決める、の3ステップです。

今日できること

自分の管理画面のCSSで、font-size と font-weight の組み合わせを数えてください。

grep -oE "font-size: [0-9]+px" your-styles.css | sort | uniq -c

同じ組み合わせが5個以上並んでいたら、階層がありません。

色数も同じように数えられます。使っているhexコードの種類を数えてみてください。

5種類を超えていたら、意味を持たない色が混ざっています。

その中から、読む人が最初に見るべき1つを選ぶところから始めてください。

余白を整え、色を絞るのはそのあとです。順番を守ると、直すたびに画面が良くなっていきます。

余白と色数は、grepでほぼ機械的に数えられます。階層だけは、自分の判断で1つ選ぶ必要があります。

余白と階層と色数は、センスではなく手順です。3つとも、数えたり選んだりできる作業だからです。
