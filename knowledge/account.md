## 主カテゴリ

**Claude Code の運用と保守 — 動かし続けるための知識**

### 選んだ理由

| 条件 | 判定 | 根拠 |
|---|---|---|
| 参入可否 | ○ | `ai-tech.md` の4条件をすべて満たす |
| 有料noteの型 | **道具型が主流** | 確認した3アカウントすべてが道具型（スキルファイル・スクリプト一式・プロンプトパック） |
| `profile.md` との整合 | ○ | 手順と失敗の記録は実績を要さない |
| 空白地帯 | 3つ | 保守・トラブルシューティング / コスト管理 / 壊れにくい設計 |
| 週5本以上の運用実例 | あり | 江守義樹氏が「1日1本を人手ほぼゼロ」を実証 |
| 1年以内に伸びた例 | あり | 参入者の大半が2025〜2026年開始。先行者利益が固まっていない |

### 他ジャンルを落とした理由

| ジャンル | 判定 | 理由 |
|---|---|---|

| 副業・収益化 | **✕** | 確認した4アカウントすべてが「月30万」等の実績を根拠にする**体験談型**。`profile.md` の「書けないこと」と正面から衝突する |

## 最重要の制約 — 直接競合を避ける

**「note投稿の自動化そのもの」を主題にしない。**

江守義樹氏（`brave_lupine5275`）が「有料noteの自動生成・投稿の自動化」を5,000円で商品化済みである。
スクリプト一式・プロンプト＆スキルパック・セットアップ手順書まで含まれており、
**本プロジェクトと同一領域**にあたる。

| 競合が売っているもの | このアカウントが扱うもの |
|---|---|
| **作り方**（パイプラインの構築） | **動かし続ける方法**（運用・保守・コスト） |
| 導入して動かすまで | 動いたあとに壊れたとき |
| 成功したときの構成 | **失敗したときにどこを見るか** |

この線を越えると差別化がなくなる。`weekly-research` はこの区別で範囲外を判定する。

## サブカテゴリ

主カテゴリの**内側**を3つに分割する。別ジャンルを足さない。

### 1. トラブルシューティング

動かないときにどこを見るか。**空白地帯1に対応する。**

- スキルが起動しない／サブエージェントが呼ばれない
- 設定ファイルの記述が効いていない
- 生成が途中で切れる
- ゲートが構造的に通らない

> 調査範囲では、成功事例と入門記事が中心で、**運用後フェーズや失敗の記録を扱う記事はほぼ見当たらなかった。**

### 2. コストとトークン設計

消費を減らす設計。**空白地帯3に対応する。**

- 何にトークンを使っているかの見立て
- LLM に考えさせない判定をコードへ移す
- モデルとエフォートの配分
- サブスク枠に収める構成

> 調査範囲では、個人開発者向けのコスト管理ノウハウは**見つからなかった。**

### 3. 壊れにくい設計

続けられる構成の作り方。

- スキル定義・エージェント定義の書き方
- 判断基準を持たせる方法
- 依存関係の切り方
- 自動化を止めない仕組み

**この3つの外は書かない。**

## ペルソナ

### どんな人か（行動で書く）

**Claude Code を導入して動くようにはなったが、スキルが起動せず frontmatter を3回書き直した人。**

もしくは、サブスクの上限に当たって止まり、何が原因か分からないまま作業を中断した人。

> 「効率化に興味がある人」ではない。**もう手を動かして、詰まっている人**である。

### 何を信じているか

- AI に任せれば作業は減るはずだ
- 動いているうちは問題ない
- 詰まったら検索すれば誰かが書いているだろう

### 何を欲しがっているか

- 表面: 目の前のエラーを解消したい
- 本当は: **同じことで二度詰まりたくない**。原因の見立てを持ちたい

### 何を感じているか

- 入門記事は読んだが、その先が書かれていない
- 動いている構成を壊すのが怖い
- トークンを何に使っているのか把握できていない

### 支払い意欲

**中〜高**

時間とコストの削減に直結する。ただし読者はエンジニア寄りで「自分で調べる」傾向があるため、
**調べる時間より安いと感じられる価格**でなければ払わない。

> `letter-audit` の B3（恐怖の種類と客層の整合）はここを見る。
> 地獄は「お金がない」ではなく**「同じ問題で何度も止まる」「気づかないうちにトークンを浪費する」**に置く。

## 書かないこと

`weekly-research` はこれを見て在庫から除外する。

1. **note投稿の自動化そのものの作り方** — 直接競合と同一になる（上記の制約）
2. **入門・インストール手順** — 既に飽和している。調査で確認した3アカウントすべてが扱っている
3. **非エンジニア・業種特化のプロンプト集** — 空白地帯ではあるが、`profile.md` にその業種の知見がない。書けば創作になる
4. 収益額・売上に関する主張 — `profile.md` の「書けないこと」
5. 利用者数・フォロワー数の主張 — 同上
6. 他ジャンル（副業・ビジネススキル・生活）全般

> 3 は「空白地帯だが書けない」例である。**空いているから書けるとは限らない。**
> 実績が貯まっても業種知見は増えないため、当面は解禁しない。

## 調査の制約（把握しておくこと）

**スキ率を算出できていない。** note.com は JS レンダリングのため、フォロワー数・スキ数・PV を
機械的に取得できなかった。代わりに以下を traction の代理指標として使っている。

- 価格改定履歴（値上げ = 売れている痕跡）
- 在庫表示（「残り4/10」= 販売実績）
- 記事の蓄積量

**この判定は推定を含む。** 実際に運用を始めて数値が取れたら、`monthly-review` で見直す。
