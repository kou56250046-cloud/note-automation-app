# thumbnail-prompt

**見出し画像は、記事より先に読まれる。** note のタイムラインでは画像とタイトルしか見えない。

このスキルは画像を作らない。**画像生成AIに渡すプロンプトを作る。**
生成そのものは人間が Gemini に貼って行う（ブラウザ自動操作は使わない方針）。

---

## 最も重要なこと

**抽象語だけのプロンプトを書かない。**

```
✕ 高級感、洗練、プロフェッショナル、シネマティック、ミニマル
    → どの記事でも同じ指示になる。結果、サムネが全部同じ顔になる
```

抽象語は生成AIが学習した「平均的な良い画像」を呼び出します。
**平均は、他の全員が出しているものと同じです。**

固定の技術仕様は使い回してよい。**変えるのは被写体・素材・色である。**

---

## 入力

| ファイル | 必須 | 何に使うか |
|---|:---:|---|
| `notes/{slug}/02-final.md` | ○ | 記事の主題。**被写体を決める材料** |
| `notes/{slug}/meta.json` | ○ | タイトル・カテゴリ・`demo` の有無 |
| `notes/{slug}/demo/after.html` | — | **配色。あればここから色を取る** |
| `knowledge/account.md` | ○ | サブカテゴリ。参照する美学を決める |

`02-final.md` が無ければ**停止する。** 記事が確定する前にサムネを決めない。

---

## 1. 被写体を決める（可変・最重要）

記事から**具体名詞**を1つ取り出す。抽象概念を絵にしようとしない。

```
記事: AIが出したLPのファーストビューを3箇所だけ直す
  ✕ 被写体「デザインの改善」        → 絵にならない
  ○ 被写体「暗い机の上に置かれた、2枚の板状のUIパネル」
```

### サブカテゴリごとの被写体の探し方

| サブカテゴリ | 被写体の候補 |
|---|---|
| **AI×Webデザイン** | 画面・パネル・グリッド・レイヤー。**記事で扱った画面そのもの** |
| **Gemini+GAS** | 表・行と列・繋がるノード・実行のフロー |
| **NotebookLM・精度向上** | 資料の束・索引・整理された棚・光の筋 |

**記事に before/after があるなら、対比の構図をそのまま使う。**
2つのものが並ぶ絵は、それだけで「比較の記事だ」と伝わります。

---

## 2. 色を決める（可変）

**`demo/after.html` があれば、そこから色を取る。**

記事の中で読者が見る画面と、サムネの色が揃います。
別々に決めると、クリックした先が別物に見えます。

```
demo/after.html の :root から
  --bg    #12111b  → 背景の基調
  --amber #ffb43d  → アクセント1色
```

デモが無い記事では、`account.md` のサブカテゴリから決める。
**この場合も「落ち着いた色」「高級感のある色」とは書かない。** 具体的な色名か hex を書く。

---

## 3. 参照する美学を**1つだけ**選ぶ

複数並べると生成AIは平均を取ります。**平均は無難で、無難は埋もれます。**

| 選ぶもの | どんなときに |
|---|---|
| **プロダクト写真**（Apple の製品ページ） | 成果物そのものを見せる記事。UI・コード・テンプレート |
| **編集写真**（雑誌の特集扉） | 考え方・設計思想が主題の記事 |
| **図解**（技術書の図版） | 手順・フロー・構造が主題の記事 |

**3つ以上を並べて書かない。** 1つに決められないなら、記事の主題が絞れていない。

---

## 4. プロンプトを組み立てる

固定部分と可変部分を分けて書く。

```
あなたは note の見出し画像を専門とするアートディレクターです。
以下の条件で16:9の画像を1枚作ってください。

## 被写体（最重要）
{ここに具体名詞。抽象概念を書かない}

## 構図
{可変。before/after があるなら対比の構図}
・中央から少し左に主題を置き、右側に余白を作る
・視線が自然に主題へ向かう配置
・浅い被写界深度。背景は軽くぼかす

## 色
・背景の基調: {hex または具体的な色名}
・アクセント: {hex}。**1色だけ**使う
・コントラストを強く。中間色を多用しない

## 質感とライティング
・{選んだ美学を1つだけ}
・斜め上からの単一光源。影の方向を揃える
・高精細、ノイズなし、4K品質

## テキスト
**画像内に文字を一切入れないでください。**
note ではタイトルが画像の上に重なるため、
中央やや右に、文字を置ける平坦な余白を確保してください。

## 避けるもの
・グラデーションを全面に敷くこと
・複数の光源で影の方向がばらつくこと
・要素を3つ以上並べること
・{記事ごとに、出てほしくない定番の絵}
```

### 「避けるもの」を必ず書く

**出してほしい形より、出してほしくない形のほうが具体的に書けます。**

生成AIは放っておくと、脳のイラスト・光る回路基板・ロボットの手・
青い網目状のネットワークを出します。**名指しで避けさせるほうが早いです。**

---

## 出力

### `notes/{slug}/06-thumbnail.md`

```markdown
# 見出し画像のプロンプト

生成先: Gemini（画像生成）
比率: 16:9

## 判断

- 被写体: {何を選んだか}
- 色: {どこから取ったか。demo/after.html の hex など}
- 美学: {1つだけ。なぜそれか}

## プロンプト

（ここにコピーして使う全文）

## 生成後の確認

- [ ] 画像内に文字が入っていないか
- [ ] タイトルを置く余白があるか
- [ ] 記事のデモと色が揃っているか
```

**プロンプト全文をコードブロックに入れる。** プレビュー画面がここを読んで
コピーボタンを出す。

---

## 物差し（これを満たさなければ出力しない）

| # | 条件 | 満たさないとき |
|---|---|---|
| 1 | 被写体が**具体名詞**である | 抽象概念を書き直す。「改善」「効率化」は絵にならない |
| 2 | 色に hex か具体的な色名が入っている | 「落ち着いた色」を書き直す |
| 3 | `demo/after.html` があるなら、そこから色を取っている | 取り直す。記事と色が揃わないと別物に見える |
| 4 | 参照する美学が**1つだけ** | 1つに絞る。絞れないなら主題が曖昧 |
| 5 | 「画像内に文字を入れない」が入っている | 入れる。note はタイトルが重なる |
| 6 | 「避けるもの」に記事固有の項目が1つ以上ある | 足す。定番の絵を名指しで避ける |
| 7 | 抽象語（高級感・洗練・プロフェッショナル）だけの節が無い | 具体に置き換える |

---

## やらないこと

- **画像を生成しない。** プロンプトを作るだけである
- **ブラウザを自動操作しない。** 人間が Gemini に貼る（CLAUDE.md の方針）
- **記事を書き換えない**
- **参照する美学を3つ以上並べない**
- **抽象語を積み重ねない。** 語を足すほど平均に近づく
