# reader-feedback

**このスキルは書き直さない。離脱する箇所を指摘して差し戻すだけ。**

無料記事の唯一の判断ゲートである。`letter-audit` が有料noteを見るのに対し、こちらは無料記事を見る。

---

## 絶対に守ること

1. **`critic` サブエージェントで実行する。** 親のコンテキストを渡さない。自分が書いた文章だと知っている状態では、書き手の意図を汲んで好意的に補完してしまう
2. **読者として読む。** 「この記事の狙いは分かるが」と考えた時点で失敗している
3. **×には行番号と修正指示を添える。** 「分かりにくい」だけでは差し戻せない
4. **褒めない。** 良かった点の列挙は不要
5. **上限は1周。** 無料記事は週5本出る。ここに2周かけるとコストが合わない

---

## 読者の前提

**スマホで読む。** 縦に細く、1画面に入る文字数は少ない。

**3スクロールで判断する。** 冒頭で「自分に関係ない」と思われたら、その先は読まれない。

**タダで読んでいる。** つまらなければ即座に離脱する。義理はない。

---

## 入力

| ファイル | 何に使うか |
|---|---|
| `notes/{slug}/01-draft.md` | 本文（行番号付きで読む） |
| `notes/{slug}/meta.json` | タイトル。**冒頭の判定に使う** |
| `knowledge/account.md` | **誰の目で読むか**（ペルソナ） |

**渡されないもの:** `00-theme.md`（選定理由）、`report.md`、執筆の経緯。
これらを知ると「なぜこう書いたか」が分かってしまい、読者として読めなくなる。

---

## 検出項目

| ID | 見るもの | 離脱する条件 |
|---|---|---|
| F1 | **冒頭3行** | 「自分に関係ない」と判断される。誰に向けた話か分からない |
| F2 | **結論の位置** | 何の話なのかが最後まで分からない。前置きが長い |
| F3 | 情報の新しさ | 知っていることばかり。検索すれば出てくる内容しかない |
| F4 | 具体性 | 抽象的で、自分の状況に当てはめられない |
| F5 | 長さと密度 | 読み終わる見通しが立たない。同じことを繰り返している |
| F6 | **出口** | 読み終わって、次に何をすればいいか分からない |

### F1 の判定 — 冒頭3行

**ここが最も多い離脱ポイントである。**

タイトルと冒頭3行だけを読み、「続きを読むか」を判断する。

```
✕ 「今回は◯◯について説明します」        → 何も言っていない
✕ 「◯◯をご存知でしょうか」              → 引き延ばし
✕ 「近年、◯◯が注目されています」        → 一般論。自分の話ではない
○ 「◯◯は設定1行で解決します。3日調べた結論です」
```

**読者が昨日か今日した（しなかった）動作が書かれているか**を見る。
「〜な人」で終わる形容は状態であり、他人事になる。

### F2 の判定 — 結論の位置

**300字以内に結論が出ているか。** 出ていなければ `drop`。

「まず前提から説明します」で始まる記事は、前提の途中で閉じられる。

### F3 の判定 — 情報の新しさ

**この記事を読まなくても得られる情報しかないか。**

公式ドキュメントに書いてあることの要約だけなら `drop`。
「実際にやったらこうだった」「ここで詰まった」が1つもなければ価値がない。

### F4 の判定 — 具体性

以下が1つもなければ `drop`。

- 手順（何を、どの順で）
- 設定値・コード・コマンドの実物
- つまずいた箇所とその回避

### F5 の判定 — 長さと密度

- **同じ主張が2回以上出てくる** → `note`
- 1500字未満 → 内容が薄い可能性。`note`
- 2500字超 → スマホでは長い。`note`

### F6 の判定 — 出口

**読者が今日できることが1つ書かれているか。**

- 0個 → `drop`（読んで終わる記事は、スキが付かない）
- 2個以上 → `note`（3つ置くと人は何もやらない）

---

## 深刻度は2段階

**中間評価を作らない。**

| severity | 意味 | 措置 |
|---|---|---|
| `drop` | **ここで読者が離れる** | 差し戻す |
| `note` | 気になるが、離脱までは行かない | 記録して通す |

**`drop` が1つでもあれば `pass: false`。**

---

## 出力

### `notes/{slug}/feedback.json`

```json
{
  "pass": false,
  "round": 1,
  "maxRounds": 1,
  "findings": [
    {
      "id": "F1",
      "severity": "drop",
      "lines": [1, 3],
      "quote": "今回は Claude Code のスキルについて説明します。",
      "why": "誰に向けた話かが書かれていない。読者は自分に関係あるか判断できず、ここで閉じる",
      "fix": "結論を先に置く。「スキルが起動しないのは frontmatter の1行が原因です」のように、何が分かる記事かを冒頭で示す"
    },
    {
      "id": "F5",
      "severity": "note",
      "lines": [42, 58],
      "quote": "つまり frontmatter が重要なのです",
      "why": "同じ主張が3箇所に出ている",
      "fix": "1箇所に絞る"
    }
  ],
  "returnTo": "daily-article"
}
```

### `notes/{slug}/05-feedback.md`

```markdown
# 読者フィードバック — {slug}

判定: 差し戻し（drop 1件 / note 1件）

## ✕ ここで離脱する

### F1 冒頭3行
- 該当行: 1-3
- 引用: 「今回は Claude Code のスキルについて説明します。」
- 状態: 誰に向けた話かが書かれていない
- 修正: 結論を先に置く

## △ 記録のみ（通す）

### F5 長さと密度
- 該当行: 42, 58 — 同じ主張が3箇所

## ○ 通過した項目
F2 F3 F4 F6
```

**通過項目はIDの羅列だけでよい。** 読むべきは ✕ と △ だけである。

---

## 差し戻しの作法

```
round 1: drop あり → daily-article に差し戻し（findings だけを渡す）
round 2: なし。1周で打ち切る
```

**`findings` だけを渡す。全文の書き直しを指示しない。**
○だった箇所を壊されると振り出しに戻る。

**1周で解消しない場合も通す。** ただし `report.md` に残った `drop` を記録する。
無料記事1本のために2周かけるより、記録して次の記事に活かすほうが合理的である。

同じ ID が3本続けて `drop` になったら、記事ではなく上流の問題である。

| 繰り返す項目 | 疑う上流 |
|---|---|
| F1（冒頭） | `daily-article` の型が守られていない |
| F3（情報の新しさ） | `weekly-research` — テーマ選定が浅い |
| F4（具体性） | `weekly-research` — `sources` が足りない |
| F6（出口） | `account.md` — ペルソナが曖昧 |

---

## やらないこと

- **書き直さない。** 指摘するだけ
- **有料noteを見ない。** それは `letter-audit` の仕事
- **文体・誤字を指摘しない。** それは `lint.py` の担当。トークンを使わずに機械が判定する
- **note で崩れる記法を指摘しない。** 同上
- **褒めない。**
