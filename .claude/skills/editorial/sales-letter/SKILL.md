# sales-letter

有料noteの無料部分は、そのままセールスレターである。ここで売上の大半が決まる。

## このスキルの仕事は3つだけ

1. **開かせる**
2. **欲しくさせる**
3. **買わない理由を潰す**

書けない人は1で止まり、売れない人は2で止まる。3まで到達させるのがこのスキルの役割。

---

## 入力

以下がすべて揃っていること。1つでも欠けたら**停止し、該当スキルの実行を促す**。

| ファイル | 何を使うか |
|---|---|
| `notes/{slug}/00-concept.md` | 商品コンセプト、約束すること |
| `knowledge/personas/{id}.md` | 購買心理3層（何を信じ／何を欲しがり／何を感じているか） |
| `knowledge/profile.md` | 自分の実績・具体的な数字・ダメだった頃の話 |
| `research/competitors/{genre}.md` | 競合が言っていること（＝外の選択肢として消す対象） |
| 価格 | pricing-strategy の出力 |

**profile.md に実数値がない場合は執筆を開始しない。** 数字のないレターは再現性を作れない。

---

## 出力

- `notes/{slug}/02-letter.md` — レター本文
- `notes/{slug}/letter-meta.json` — 構造メタ（letter-audit が読む）

`letter-meta.json` の形式:

```json
{
  "blocks": [
    {"n": 1, "type": "hook", "lines": [1, 3]},
    {"n": 2, "type": "problem", "lines": [5, 14]}
  ],
  "fearCount": 1,
  "fearBlock": 7,
  "reproducibility": ["単純化", "簡易化", "天井を下げる", "共感"],
  "closingType": "ideal-future",
  "exitActions": 1,
  "deadlineClaims": []
}
```

`deadlineClaims` には期限・値上げ・特典終了に関する記述をすべて抜き出す。ethics-line が本物かどうかを検証する。

---

## 構造（この順番で書く）

```
1.  フック          読者が「自分のことだ」と感じる一文
2.  問題の可視化    行動で名指しする
3.  理想の未来 (1)
4.  再現性 (1)      単純化
5.  理想の未来 (2)
6.  再現性 (2)      簡易化
7.  恐怖            1つだけ。回避可能な位置で止める
8.  理想の未来 (3)
9.  再現性 (3)      天井を下げる ＋ 自分以外の結果
10. 再現性 (4)      共感（自分がダメだった頃）
11. 買わない理由の除去（6つ）
12. 漏斗            断定 → 外の選択肢を消す → 出口を1つに
13. 締め            理想の未来で終わる
```

**理想の未来と再現性は必ず交互に置く。** 片方だけでは止まる。

- 理想の未来だけ → 「すごいけど自分には無理」で終わる
- 再現性だけ → 「簡単なのは分かったけど別に欲しくない」で終わる

---

## 各ブロックの書き方

### 2. 問題の可視化 — 状態ではなく行動で名指しする

読者は自分が困っていることに気づいていない。だから先に問題を可視化する。このとき**状態で書くと他人事になる。行動で書くと自分の話になる。**

```
NG  テーマが決まっていない人
OK  エディタを開いて、3日書けていない人

NG  発信が続かない人
OK  下書きが4本たまったまま、どれも公開していない人
```

**必ず、読者が昨日か今日やった（やらなかった）動作を書く。**

### 4/6/9/10. 再現性 — 4つの型をすべて使う

| 型 | やること | 判断基準 |
|---|---|---|
| **単純化** | やることを1つに絞る | 「これだけやればいい」の形。**やることを5個並べた時点で読者は無理だと判断する** |
| **簡易化** | 時間と手間を数字で出す | 1日5分／3ステップ／30日。数字が入ると読者の予定に置ける |
| **天井を下げる** | 到達点をあえて低くする | ここが一番効く。届かない100万より、届く5万のほうが財布は開く |
| **共感** | 自分がダメだった頃を書く | 今の読者と同じ場所に立っていた証拠になる |

**天井を下げるのは直感に反するが、最も効く。** 大きい数字を出すほど読者から遠くなる。`profile.md` にある最大の実績をそのまま書くのではなく、**読者が明日届く高さ**に置き直す。

天井を下げるときは、**自分以外の結果を1つ添える**。自分の数字だけだと「この人がすごい」で止まる。自分と遠くない誰かの結果があると「自分にもできる」に変わる。

### 7. 恐怖 — 1つだけ、回避できる位置で止める

理想の未来だけを見せられても人は動かない。今のままで居心地が悪くないから。「欲しいけど、今じゃなくていい」で閉じられる。だから**このまま動かないとどうなるか**を1回だけ見せる。

**条件は2つ。どちらも絶対。**

**条件1: 1つのコンテンツに恐怖は1つまで。**
地獄を連発すると記事が重くなるだけでなく、**集まる客層が変わる**。お金がない地獄ばかり書くと、お金がない人が集まる。何を地獄に置くかで客層が動くので意図的に選ぶ。

**条件2: 「もう手遅れ」にしない。**
遅刻しそうなとき人は走る。だが遅刻が確定した瞬間に走るのをやめる。**人はまだ間に合うときだけ動く。** 「今からじゃもう遅い」と書いた瞬間に読者は動かなくなる。

恐怖と絶望は違う。書くのは恐怖だけ。

### 11. 買わない理由の除去 — 6つを1つずつ潰す

少しでも欲しいと思っても、人は買わない理由を探す。読者に残る「でも」は6種類しかない。

| # | 買わない理由 | 潰し方 |
|---|---|---|
| 1 | そもそも問題があると思ってない | ブロック2で行動で名指しして可視化する |
| 2 | 再現性がなさそう | 天井を下げる ＋ 自分以外の結果を1つ添える |
| 3 | 今買う理由がない | 期限／値上げ／特典終了。**本物のものだけ使う** |
| 4 | 高いしあとでいい | 中身を分解して価値を示す。**値下げで潰さない** |
| 5 | 自分には早い | 誰向けかを書く。**向かない人も書く** |
| 6 | 本当に結果が出るのか | どこまでやれば結果が出るかを示す。**約束を狭くする** |

**#4の注意:** 価格そのものではなく、価格に納得できていない状態が問題。安くするほど「こんな値段で大丈夫か」と再現性の不安が増える。やることは「これなら高いのは納得だ」と感じてもらうこと。

**#5の注意:** 「全員におすすめです」と書くほど誰も自分ごとにしない。向かない人を正直に書くと、向く人の確信が上がる。

**#6の注意:** ボリュームを増やしても不安は消えない。消えるのは「どこまでやれば結果が出るか」が見えたとき。だから「何でもできます」と広げず、「これはできないが、これは絶対できる」に絞る。**約束を狭くするほど信じてもらえる。**

### 12. 漏斗 — 選択肢を1つに絞っていく

レターは漏斗の形をしている。入口は広く、出口は狭く。人は選択肢が多いと選ばずに閉じる。

1. **断定する** — 「これが正解です」と言い切る。迷わせた時点で読者は決めるのをやめる
2. **外の選択肢を消す** — 他のやり方に触れ、なぜそっちではないかを先に書く
3. **最後の行動を1つだけにする** — 買う／登録する／フォローする。3つ置くと人は全部やらない

### 13. 締め

**必ず理想の未来で終える。** 恐怖や注意書きで終わらせない。

## 文体

- 一文を短く。改行を多めに
- 会話のようなテンポ
- `knowledge/voice.md` の禁止表現に従う
- 誇張した形容詞より、具体的な数字と固有名詞

---

## よくある失敗（生成後に自分で確認する）

1. **欲しくさせる側だけ厚い** — 理想の未来が3000字あって、買わない理由が1つも潰れていない。最も多い失敗
2. **地獄を盛って客層が荒れる** — 不安を煽るほど反応は増えるが、集まった人が自分の客とは限らない
3. **外の選択肢を消していない** — 欲しくなっても、他の発信者の選択肢が残っていると選ばれない

## 書き終えたら

`letter-audit` を必ず実行する。**自己判断で「良い出来だ」と結論しない。**
このスキルは書く役であって、判定する役ではない。判定は独立したコンテキストを持つ `critic` が行う。
