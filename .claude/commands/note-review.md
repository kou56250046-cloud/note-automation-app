売上の3因数のうち、どこが詰まっているかを診断します。

**月初に手で回してください。** Routines は廃止したので、自動実行はありません。
途中で数字を見たくなったときも、このコマンドで実行できます。

月初に回すときは、診断のあとに以下も実行してください（旧 `monthly-review` の担当分です）。

1. `profile-accumulator` — 運用ログと実測から「言える実績」を `profile.md` に追記する
2. `revenue-maximizer` — 顧客数 × 単価 × 購入回数 でボトルネックを1つに絞る
3. `type: experience` を解禁できるかを判定する（`profile-accumulator` の判定に従う）

## 手順

### 1. 数値を集める

| ファイル | 無いとき |
|---|---|
| `research/market/{最新}.json` | **これが無ければ停止**し、`python scripts/note_market.py` を促す |
| `notes/*/meta.json` | 停止。記事が1本も無い |
| `data/metrics.json` | 「未取得」と記録して続行 |
| `data/revenue.json` | 「販売実績なし」と記録して続行 |

**`market` データは `.md` の要約表を読んでください。**
数値の全量が必要なときだけ `.json` を開きます。生データはコンテキストを汚します。

### 2. `revenue-maximizer` を実行する

顧客数 × 単価 × 購入回数 の3因数を、**市場水準との比**で見ます。

- 測定できない因数をボトルネックにしない
- 顧客数が市場水準に届くまで、単価と購入回数を触らない
- **次の1手は1つだけ**

### 3. `data/bottleneck.json` に出力する

### 4. 報告する

## 報告の形式

```
ボトルネック: 顧客数（市場比 0.11）

  スキ中央値 7 に対し、市場の人気記事は 62。

次の1手: 投稿タグを空白タグへ寄せる

  直近5本が ClaudeCode（需要÷供給 0.069）と生成AI（0.043）を
  主軸にしていました。1日400件以上に押し流される場所です。
  Webデザイン(7.80) / NotebookLM(6.28) へ寄せます。

判定できなかったもの: 購入回数
  販売実績が data/revenue.json にありません。

触らないもの: 単価
  市場比 1.85 で詰まっていません。顧客数が市場水準に届くまで動かしません。
```

## やらないこと

- **改善策を並べない。** 5個出すと人は何もやりません
- **推測で数値を作らない。** 測れないものは「未測定」と書きます
- **`account.md` を書き換えない。** カテゴリの変更は影響範囲が大きいため、
  判断材料を添えて人間に回します
- **記事を書かない。** テーマへの反映は `weekly-research` の担当です
