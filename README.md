# note-factory

Claude Code で「ひとり出版社」を組み、リサーチから記事生成までを自動化するリポジトリ。

**週7本を投稿する。** 無料記事5本＋有料note 2本。

---

## これは何か

有料noteと無料記事を作る工程を分解し、Claude Code の機能（Routines / Skills / Subagents）と GitHub Actions に割り当てたもの。

続けられるかどうかを、**意志力の問題から設計の問題に変える**ことが目的である。

### 人間の仕事は2つだけ

1. プレビュー画面から本文をコピーして、note に貼って投稿する
2. ダッシュボードで管理する

それ以外（調査・リサーチ・分析・テーマ決め・記事生成）はすべて機械側で完結する。テーマ選定すら自動である。

**確認を求めるために処理は止まらない。** 止まるのは、入力ファイルが欠けているときだけ。

### 二層モデル

部署ではなく**周期**で分ける。リサーチを日次でやるとトークンが尽きるからである。

| 層 | やること | 周期 |
|---|---|---|
| 週次リサーチ | 1週間分のテーマ7本を仕込む | 月曜1回 |
| 日次生成 | 在庫から1本引いて記事にする（**web検索なし**） | 毎日 |
| 決定論ゲート | 文体・重複・note記法を機械判定（**トークン0**） | push のたび |

日次生成が web 検索をしないことが、毎日投稿を成立させている唯一の理由である。

### 人が見ないぶん、機械が自分を落とす

| ゲート | 見るもの | 対象 | 上限 |
|---|---|---|---|
| `lint.py` | 文体・表記・note で崩れる記法 | 全記事 | — |
| `dedup.py` | 既出記事との重複 | 全記事 | 0.85超でブロック |
| `reader-feedback` | 離脱しないか | 無料記事 | 1周 |
| `letter-audit` | 売れるか（16項目） | 有料note | 2周 |
| **`ethics-line`** | 偽の限定・盛った恐怖がないか | **全記事** | **上限なし** |

`ethics-line` だけ上限がないのは、景品表示法・特定商取引法に関わるため。他は品質の問題だが、これは法的な問題である。妥協しない。

**上2つはトークンを消費しない。** 決定論で判定できるものを LLM に考えさせないのが、このシステムのコスト設計の中核である。

## クイックスタート

### 1. 初回セットアップ

```
/note-init
```

`account-research` が note で伸びているアカウントを解剖し、`account-design` が**主カテゴリ1つ＋サブカテゴリ2〜3つ**とペルソナを確定する。

**ヒアリングはない。** 一問も聞かれずに `knowledge/account.md` が生成される。ここで決まったカテゴリが、以降すべての記事の範囲になる。

### 2. 1本作ってみる

```
/note-daily
```

「お願いします」と言うだけでも同じコマンドが起動します。

`themes.md` の在庫から今日のテーマを1本引いて記事にする。無料記事なら1500〜2500字、有料noteならレター＋本文が生成され、ゲートを通過するまで自動で回る。

### 3. note に投稿する

```
/note-preview
```

`localhost:5173` が開く。投稿待ちの一覧から記事を選び、「本文をコピー」を押して note に貼るだけ。

**書式は保持される。** クリップボードに `text/html` を書き込むので、見出し・太字・リスト・引用・区切り線がそのまま入る。

有料noteは「無料部分をコピー」「有料部分をコピー」が分かれている。無料部分を貼る → note で有料エリアを設定 → 有料部分を貼る、の順で作業する。

> **ブラウザ自動操作は使わない。** note のエディタは重く、スクリーンショットが画像トークンを食う（1本20〜40k tokens）。HTML からコピペするほうが速く、安く、落ちない。

## コマンド

| コマンド | 動作 |
|---|---|
| `/note-init` | 初回のみ。カテゴリとペルソナを自動決定する |
| **`/note-daily`** | 今日の記事を1本作る（**「お願いします」でも起動する**） |
| **`/note-preview`** | `localhost:5173` で投稿キューを開く（週1回の運用作業） |
| `/note-revise {slug} "指示"` | 差し戻して再生成 |
| `/note-letter {slug}` | 有料noteのレター診断ループを回す |

## 自動で動くもの

### Routines（Anthropic クラウド。PC を起動していなくても動く）

| Routine | タイミング | やること |
|---|---|---|
| `daily-build` | **月火水金土 06:00** | 在庫から無料記事を1本作る |
| `weekly-research` | 月曜 07:00 | 1週間分のテーマ7本を仕込む |
| `monthly-review` | 月初 08:00 | ボトルネック診断 → 今月の打ち手 |

Pro プランの実行上限は5回/日。**最大消費は「月初が月曜と重なった日」の3回**で、予備2枠が手動実行用に残る。

**木・日（有料noteの日）は Routine が動かない。** 有料部分を追跡しないため、クラウドで生成すると手元に残らない。ローカルで `お願いします` を実行する。

### GitHub Actions（トークンを一切消費しない）

| ワークフロー | タイミング | やること |
|---|---|---|
| `lint-and-dedup` | `notes/` への push | 文体・note記法・重複を判定 |
| `fetch-metrics` | 毎朝 06:30 | note の数値を取得して暗号化 |
| `stock-alert` | 毎朝 07:00 | ネタ在庫が3本未満なら Issue |
| `weekly-digest` | 日曜 20:00 | 週次サマリーを Issue 化 |
| `deploy-dashboard` | `data/` への push | ダッシュボードを Pages にデプロイ |

**プレビュー生成は Actions に置かない。** public repo の artifact は誰でもダウンロードできるため、`/note-preview` がローカルで生成する。

> **Actions で記事生成はしない。** Claude Code Action は API キーによる従量課金でサブスク枠外になるため、生成は Routines かローカルに置く。

**`stock-alert` が最も重要。** ネタ在庫の枯渇が、毎日投稿の唯一の停止要因である。

## 有料noteの型

**実績がなくても有料noteは作れる。** ただし型を分ける必要がある。

| 型 | 再現性の根拠 | `profile.md` | 例 |
|---|---|---|---|
| **`tool`（道具型）** | **成果物そのものの検証可能性** | **不要** | スキル定義集、プロンプト集、設計図 |
| `experience`（体験談型） | 書き手の実績 | **必須** | 「月5万を達成した手順」 |

道具型は「買った人が手元でコピペして動かせるか」で再現性を担保する。書き手が何者かは関係ない。動くかどうかはコードとテンプレートが証明する。

`letter-audit` の判定もこの型で分岐する。**実績が貯まるまでは `tool` だけを作る。**

```
├── notes/{slug}/          # 記事単位の成果物
├── preview/               # プレビューHTML（git 管理外）
├── data/                  # metrics.json / history.jsonl / revenue.json
├── scripts/               # build-preview.mjs / serve.mjs / lint.py / dedup.py

```

記事1本の成果物:

| ファイル | 中身 |
|---|---|
| `00-theme.md` | 引いたテーマと選定理由 |
| `01-draft.md` → `02-final.md` | 本文 |
| `meta.json` | タイトル / カテゴリ / ハッシュタグ / type / 公開予定日 |
| `report.md` | **判断ログ** |
| `ethics.json` | 線引きゲートの検出結果 |

有料noteでは `00-concept.md`（`productType` を含む）／`02-letter.md`／`03-draft.md`／`audit.json` が追加される。

**`report.md` が最も重要。** 人が過程を見ないので、記録がないとシステムを改善できない。

## リポジトリは public。有料部分だけ追跡しない

リポジトリ: https://github.com/kou56250046-cloud/note-automation-app

public にすることで GitHub Pages と Actions（実行時間無制限）の無料枠を使える。

**ただし有料noteの本文は追跡しない。** public repo に置けば誰でも読め、商品価値が消える。

| 対象 | 追跡 | 理由 |
|---|:---:|---|
| `notes/**/03-draft.md` | ✕ | **有料部分の本文** |
| `preview/` | ✕ | 生成HTMLに有料部分が含まれる |
| `secrets/` | ✕ | 合言葉 |
| `notes/**/02-letter.md` | ○ | note 上でも無料公開する部分 |
| `data/` | ○ | 暗号化済み |

**この制約から2つが決まる。**

1. **有料noteの生成はローカル実行のみ。** Routines はクラウドで動いてコミットするため、追跡しないファイルを手元に残せない。`daily-build` は無料記事だけ（月火水金土）を担当し、有料noteは木・日にローカルで作る
2. **プレビューの生成もローカルのみ。** public repo の Actions artifact は誰でもダウンロードできる

ダッシュボードは `data/` が暗号化済みなので、GitHub Pages で公開してスマホから見られる。

## 開発ロードマップ

| ステップ | 内容 | 状態 |
|---|---|---|
| 0 | `.gitignore` 整備（有料部分を除外）＋ remote 接続 | — |
| 1 | `account-research` + `account-design` + `/note-init` | — |
| 2 | `weekly-research` + 在庫管理 | — |
| **3** | **`lint.py` + `dedup.py` + Actions** | — |
| 4 | `daily-article` + `daily-build` | — |
| 5 | `build-preview.mjs` + `/note-preview` | — |
| 6 | `sales-letter` / `letter-audit` の型対応 | — |
| 7 | `fetch-metrics` + `profile-accumulator` | — |
| 8 | 体験談型の解禁 + 営業部 | — |

**ステップ3を4より先にする理由:** 品質ゲートが動く前に毎日生成を始めると、重複記事とトーンのぶれた記事が積み上がる。**初期30本がアカウントの初期評価をほぼ決めてしまう。** 順番を入れ替えてはいけない。

### ウォームアップ期間

いきなり毎日投稿にしない。note のアルゴリズムは投稿頻度だけでなくスキ率・読了率を見るため、読まれない記事を毎日出すとアカウント評価はむしろ下がる。

| 期間 | 頻度 | 目的 |
|---|---|---|
| 第1〜2週 | 無料3本 + 有料1本 | 反応の確認とトークン実測 |
| 第3週〜 | 無料5本 + 有料2本 | 数値が取れてから本番頻度へ |

## 設計を壊さないための6つの禁止事項

1. **生成だけのスキルを作らない。** すべてのスキルは物差しを持つ。**物差しはコードでもよい**
2. **依存関係を飛ばさない。** 前工程の出力がなければ停止し、実行すべきスキル名を伝える
3. **実績・体験・第三者の結果を創作しない。** 足りなければ書かずに「足りない」と報告する
4. **カテゴリの範囲外を書かない。** 散らすと note のアルゴリズムに拾われなくなる
5. **書き手に自己評価をさせない。** 判定は独立コンテキストのサブエージェントが行う
6. **ゲートを人間の承認で代替しない。** 「これでよろしいですか」はゲートを通したことにならない
