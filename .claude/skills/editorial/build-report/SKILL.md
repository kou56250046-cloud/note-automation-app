# build-report

**人間が過程を見ない。だから記録がないと改善できない。**

このスキルは記事の品質を上げない。**システムの品質を上げる。**

---

## 唯一の判定基準

> **この記録を読んだ人が、次に何を直せばよいか分かるか。**

分からなければ、その記録は書いた意味がない。以下を満たすこと。

| 条件 | 満たさない例 | 満たす例 |
|---|---|---|
| 判断に理由が添えられている | 「テーマAを選んだ」 | 「テーマAを選んだ。強み5/市場性4。次点Bは市場性2で落とした」 |
| 数値に出所がある | 「スキ率が高い」 | 「スキ率3.2%（`data/metrics.json`）」 |
| 事実であって評価でない | 「良い記事ができた」 | 「reader-feedback の drop 1件を修正した」 |
| 次工程への申し送りがある | （なし） | 「`sources` が2件しかなく手順を補えなかった。weekly-research へ」 |

## 入力

| ファイル | 何を拾うか |
|---|---|
| `notes/{slug}/00-theme.md` | 選定理由・スコア・次点 |
| `notes/{slug}/feedback.json` | `reader-feedback` の結果（無料記事） |
| `notes/{slug}/audit.json` | `letter-audit` の結果（有料note） |
| `notes/{slug}/ethics.json` | **`ethics-line` の検出（全件）** |
| `notes/{slug}/meta.json` | タイトル・type・文字数 |

無いファイルは「実行されていない」と書く。**推測で埋めない。**

## 必ず書くこと

CLAUDE.md が指定している5項目である。**1つでも欠けたら記録として不完全。**

1. **どのテーマをなぜ選んだか**（スコアと次点）
2. **各ゲートで何回差し戻したか、何が×だったか**
3. **`ethics-line` が何を削除・修正したか — 全件**
4. **`severity: review` として人間に回した項目**
5. **`lint.py` / `dedup.py` の警告**（ブロックされなかったものも含む）

### 3 を省略してはいけない理由

`ethics-line` は自動で修正する。**何を消したかを人間が知らないまま運用するのは危険である。**

特に E1（偽の限定）は、書いた本人が「実行するつもりだった」場合に削除が誤りになる。
ログを見て復活させる判断は人間に残す。

### 5 を書く理由

ブロックされなかった警告こそ見る価値がある。**ネタの反復は徐々に進む。**
`dedup.py` の 0.70〜0.85 が続いていたら、それは在庫が痩せている信号である。

---

## 書いてはいけないこと

| ✕ | なぜ |
|---|---|
| 「良い記事ができました」 | 評価であって事実ではない。**書き手に自己評価をさせない**（CLAUDE.md ルール5） |
| 「順調です」 | 同上 |
| 「おそらく〜だと思われる」 | 推測。事実だけを書く |
| 実行していないゲートの結果 | 「実行していない」と書く |
| 出所のない数値 | `data/` か既存ファイルに根拠があるものだけ |

## 有料noteのとき

以下を追加する。

```markdown
## 商品設計

productType: tool（道具型）
価格: ◯◯円（pricing-strategy の根拠: ...）

## letter-audit

判定: 合格（16/16） / 1周
round 1: C2「再現性がなさそう」で不合格
  → 成果物の実物を数行追加して解消

## 有料部分の扱い

03-draft.md はローカルにのみ存在する（.gitignore 対象）。
文字数: {n} 字
lint.py / dedup.py はローカル実行で通過済み。
```

## この記録の使われ方

| 読む人 | 何を見るか |
|---|---|
| `monthly-review` | ゲートの傾向、繰り返し出る指摘 |
| `profile-accumulator` | 「書けなかったこと」から、測るべき数値を拾う |
| `weekly-research` | 申し送りを読んで在庫の質を上げる |
| ダッシュボード | 自動運転ログタブに表示する |

**書きっぱなしにならない。** だから形式を揃える。
