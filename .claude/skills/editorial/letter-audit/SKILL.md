# letter-audit

**このスキルは書き直さない。判定して差し戻すだけ。**

人間が最終確認をしない完全自動フローでは、機械が自分を落とす仕組みが必要になる。それがこのスキル。

## 絶対に守ること

1. **`critic` サブエージェントを使って実行する。** 親のコンテキストを渡さない。自分が書いた文章だと知っている状態では正直な×が出せない
2. **判定は真偽値で返す。** 「やや弱い」「もう少し」といった中間評価を作らない。○か×か
3. **×には必ず行番号と修正指示を添える。** 「改善の余地がある」だけでは差し戻せない
4. **褒めない。** 良かった点の列挙は不要。通過した項目は○とだけ書く
5. **×が1つでも残れば `pass: false`。** 15/16 は不合格

---

## 入力

- `notes/{slug}/02-letter.md` — レター本文（行番号付きで読む）
- `notes/{slug}/letter-meta.json` — 構造メタ
- `knowledge/personas/{id}.md` — 誰の目で読むか

---

## 出力

- `notes/{slug}/04-audit.md` — 人間が読む判定レポート
- `notes/{slug}/audit.json` — ワークフローが分岐に使う判定結果

```json
{
  "pass": false,
  "round": 1,
  "score": "13/16",
  "failures": [
    {
      "id": "C3",
      "label": "今買う理由がない",
      "lines": [88, 96],
      "why": "期限・値上げ・特典終了のいずれも記述がない。読者は「後で買う」を選べる状態のまま",
      "fix": "値上げ予定を明記するか、初期購入者への追加特典を設定する。ただし実行する予定のないものは書かない"
    }
  ],
  "returnTo": "sales-letter"
}
```

## 判定16項目

### A. 欲しくさせる側（4項目）

| ID | 判定項目 | ×になる条件 |
|---|---|---|
| A1 | 理想の未来と再現性が交互に来ているか | 理想の未来が2つ以上連続、または再現性が2つ以上連続している |
| A2 | 最後が理想の未来で終わっているか | 締めが恐怖・注意書き・箇条書き・価格説明で終わっている |
| A3 | 再現性が4つで作られているか | 単純化／簡易化／天井を下げる／共感 のうち欠けているものがある |
| A4 | 約束が「何でもできる」になっていないか | 効果を3つ以上並べている、または対象範囲を限定していない |

**A3の見分け方**

- 単純化 = やることが1つに絞られているか。**5個並んでいたら×**
- 簡易化 = 時間・回数・期間の**具体的な数字**があるか
- 天井を下げる = 到達点が読者の手の届く高さか。**自分の最大実績をそのまま提示していたら×**
- 共感 = 自分がダメだった頃の**具体的なエピソード**があるか

### B. 恐怖（3項目）

| ID | 判定項目 | ×になる条件 |
|---|---|---|
| B1 | 恐怖は1つだけか | 2つ以上の地獄が描かれている |
| B2 | 「もう手遅れ」になっていないか | 「今からでは遅い」「既に手遅れ」に相当する記述がある |
| B3 | 何を地獄に置いたか。集まる客層は狙い通りか | 地獄の種類がペルソナの支払い意欲と矛盾している |

**B3の判定方法:** 地獄が「お金がない」なら、集まるのはお金がない人になる。`personas/{id}.md` の支払い意欲が中〜高なら矛盾するので×。地獄は「時間を失う」「後発に抜かれる」など、支払い能力のある層が反応するものに置き換えさせる。

### C. 買わない理由6つ（6項目）

| ID | 買わない理由 | ×になる条件 |
|---|---|---|
| C1 | そもそも問題があると思ってない | 問題の名指しが**状態**で書かれている（行動になっていない） |
| C2 | 再現性がなさそう | 天井を下げていない、または自分以外の結果が1つも無い |
| C3 | 今買う理由がない | 期限・値上げ・特典終了のいずれも無い |
| C4 | 高いしあとでいい | 中身の分解が無い、または**値下げ・割引で解決しようとしている** |
| C5 | 自分には早い | 対象読者の明示が無い、または**向かない人を書いていない** |
| C6 | 本当に結果が出るのか | 「どこまでやれば結果が出るか」の到達点が示されていない |

**C1の判定:** ブロック2の文を見て、読者が昨日か今日した（しなかった）**動作**が書かれているか。「〜な人」で終わる形容は状態なので×。

**C4の判定:** 「今だけ安く」「特別価格」で納得を作ろうとしていたら×。安いほど再現性の不安が増える。中身を分解して「これなら高いのは納得だ」に持っていくのが正解。

### D. 漏斗（3項目）

| ID | 判定項目 | ×になる条件 |
|---|---|---|
| D1 | 断定しているか | 「〜かもしれません」「人によります」で逃げている箇所がある |
| D2 | 外の選択肢に触れて消したか | 他のやり方に一度も言及していない、または言及しただけで消していない |
| D3 | 最後に提示する行動は1つだけか | 出口が2つ以上ある（買う＋フォロー＋登録 など） |

## 差し戻しのルール

```
round 1: ×あり → sales-letter に差し戻し（failures をそのまま渡す）
round 2: ×あり → sales-letter に差し戻し（残った failures のみ）
round 3: ×あり → 打ち切り。pass: false のまま人間に回す
```

**3周で解消しない場合は自動修正を諦める。** 同じ指摘が3回残るのは、レターの問題ではなく上流（コンセプトか価格か対象読者）の問題である可能性が高い。`04-audit.md` の末尾に「上流の見直しを推奨」と明記し、疑わしい工程名を書く。

**差し戻し時は failures だけを渡す。** レター全文の書き直しを指示しない。○だった箇所を壊されると振り出しに戻る。

---

## 04-audit.md の形式

```markdown
# レター診断 — {slug} / round 1

判定: 不合格（13/16）

## × 残っている項目

### C3 今買う理由がない
- 該当行: 88-96
- 状態: 期限・値上げ・特典終了のいずれも記述がない
- 修正: 値上げ予定を明記する。ただし実行する予定のないものは書かない

## ○ 通過した項目
A1 A2 A3 A4 B1 B2 B3 C1 C2 C4 C5 C6 D1
```

**通過項目はIDの羅列だけでよい。** 説明を書かない。読むべきは×だけ。
