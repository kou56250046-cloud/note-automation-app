### ★ 成果物側のバグを修正した（本文の修正では足りなかった）

auditor の指摘の中核は本文ではなく**スクリプトの実装**だった。

```js
// 修正前
const FONT_SIZE_RE = /font-size\s*:\s*[^;]+;?/g;
```

`var(...)` の中身を除去したあとに残る `font-size: ;` の**空白1文字に `[^;]+` がマッチする。**
つまり **`font-size: var(--font-size-base)` という正しい書き方が、毎回「生の font-size」として
誤検出される。** 読者の実プロジェクトで必ず起きる。

```js
// 修正後
const FONT_SIZE_RE = /font-size\s*:\s*[^;\s][^;]*;?/g;
const HAIRLINE = new Set(["0px", "1px"]);
```

1文字目に `[^;\s]` を要求して、値が空になる行を対象外にした。
あわせて境界線のヘアライン（0px / 1px）を PX 検出から除外した。
`--space-1` は 4px なので、置き換えると線が太くなるためである。

**検証した。** `03-draft.md` からスクリプトを抽出して実行した。

- `var()` だけを使った CSS → **検出0件**（修正前は2件の誤検出）
- 生の `#fff` / `13px` / `15px` を混ぜた CSS → **3件とも検出**

6章末に「作例に `check-tokens.mjs` をかけると出るもの」を追加し、
幅の 200px / 360px は幅用トークンを用意していないため**出てよい検出**であること、
ヘアラインは除外していること、正しく参照している行は出ないことを明記した。
