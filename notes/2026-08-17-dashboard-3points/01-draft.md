AIに出させたダッシュボードのグラフは、見た目ほど正確ではありません。

棒グラフの目盛りが0から始まっていなかったり、系列ごとに違う色がついていたりします。

一番大事な数字が、画面の隅に置かれていることもあります。

直す場所は3つだけです。色数、目盛り、並びです。

この3つを直すと、同じ数字のまま伝わり方が変わります。


## 「動くけど読めない」の中身

指示はたいてい「売上ダッシュボードを作って」の一言です。

それでもグラフはひととおり出てきます。棒グラフも、KPIカードも崩れてはいません。

それでも、上司や取引先に画面を見せたとき、質問が返ってくることがあります。

「このグラフ、なぜこんなに急に伸びているんですか」という質問です。

スクリーンショットを撮って、結局共有をためらった人もいるはずです。グラフの見た目に説明を求められると、その場で答えに詰まります。

答えを探すと、目盛りが0からではなく90や100あたりから始まっていることに気づきます。

AIは、値の差が見えやすいようにグラフの軸を自動で調整します。

グラフ描画ライブラリには、データの最小値付近から軸を始める設定を既定にしているものがあります。差を強調する狙いがある一方、読み手には比率としてそのまま伝わってしまいます。

差を見せることが目的なら効果的です。ただし読む人は、軸の開始位置までは確認しません。

棒の高さの比率だけを見て、実際より大きな変化だと受け取ります。

色についても同じことが起きます。カテゴリごとに赤・緑・紫・オレンジが割り振られ、意味のある色分けには見えません。

作例を用意しました。左はAIの出力によくある形をそのまま残したもの、右が直したものです。

左のHTMLには、どこが問題なのかを示す説明コメントだけをこちらで足してあります。

https://kou56250046-cloud.github.io/note-automation-app/demo/2026-08-17-dashboard-3points/

同じ2つのグラフと1つの数値カードを使っています。並び順と使う数字も同じです。

違うのは、色の数、軸の始点、そしてカードの配置だけです。


## 手1: 色数を1色＋強調1色に絞る

before の月次推移グラフは、6本の棒それぞれに違う色を使っていました。

```html
<!-- before: 同じ系列なのに棒ごとに色を変えている -->
<rect fill="#ff5f6d"/>
<rect fill="#38ef7d"/>
<rect fill="#4a6cf7"/>
<rect fill="#ffd200"/>
<rect fill="#8e2de2"/>
<rect fill="#11998e"/>
```

6本の棒は、同じ指標(月次の売上)の時系列です。系列が1つなら、色を分ける理由がありません。

カテゴリ別のグラフも同様でした。4つの棒に、赤・緑・紫・オレンジを個別に割り当てていました。

色数が多いと、読む人は「色の違いに意味があるはずだ」と考えます。存在しない対応関係を、頭の中で探してしまいます。

after では、両方のグラフを基本の1色にそろえました。最も重要な棒だけに、アクセント色を使っています。

```html
<!-- after: 基本は1色。最新月と最大値だけアクセント -->
<rect fill="#85796a"/> <!-- 1月〜5月 -->
<rect fill="#2456e0"/> <!-- 6月(今月) -->
```

アクセントを当てる対象は、読む人が最初に確認したい場所に合わせて選びます。

今回は月次推移で「直近の月」、カテゴリ別で「最大の値」を選びました。

色を絞ると、目が最初にどこへ向かえばいいかが決まります。


## 手2: 目盛りを0から始める

before の月次推移グラフは、軸の始点が90でした。

100万円から145万円への変化は、実際には1.45倍です。

軸を90から150までにすると、同じ変化が見た目では5倍近くに伸びて見えます。

```
before: 軸の範囲 90〜150（差が誇張される）
after:  軸の範囲  0〜150（実際の比率で見える）
```

after では軸を0から始め、最大値より少し上まで取っています。

同じ6つの数字を使っていても、棒の高さの差はずっと小さくなります。

目盛りを0から始めるのは、AIが作ったグラフを直すときに、最初に確認すべき箇所です。

色や配置より先に、この1点だけは数値で確認できます。

目盛りのラベルを見て、一番下が0かどうかを見てください。0でなければ、それだけで比率が誇張されています。

カテゴリ別のグラフは、before の時点でも0から始まっていました。今回、目盛りを直したのは月次推移のグラフだけです。


## 手3: 最重要の数値を左上に置く

before では、月次推移とカテゴリ別のグラフを上段に大きく置いていました。

今月の売上という一番大事な数字は、右下に小さく添えているだけでした。

画面を開いた人が最初に目を向けるのは、たいてい左上です。

そこにグラフの装飾が並び、肝心の数字は視線の最後にようやく出てきます。

after では、今月の売上のカードを画面の最上段、左端に大きく配置しました。

```css
/* before: 数値カードは右下、小さい */
.card.summary { grid-area: summary; justify-self:end; align-self:end; width:220px; }

/* after: 数値カードは最上段、全幅で大きい */
.card.summary { grid-area: summary; }
.grid { grid-template-areas: "summary summary" "trend category"; }
```

グラフは、数値カードの下に置き直しました。

並びを変えるだけなら、コードの追加はほとんど要りません。grid-template-areas の並び順を書き換えるだけです。

配置の変更は、見た目の直し方の中でいちばん手数が小さい作業です。

数値そのものは動かさないので、失敗しても元の配置に戻しやすいところでもあります。


## 実際に投げた指示

after を作るときに使った指示の全文です。

```
このダッシュボードを直してください。手順を分けます。

1. 色数
   月次推移の棒グラフが、6本とも違う色になっています。
   同じ指標の時系列なので、基本は1色にそろえてください。
   直近の月(6月)だけ、アクセントカラーで強調してください。
   カテゴリ別グラフも同様に、基本は1色にそろえ、
   最も値が大きいカテゴリだけアクセントカラーにしてください。

2. 目盛り
   月次推移グラフの縦軸が90から始まっていて、
   実際の変化より急に伸びているように見えます。
   縦軸を0から始まる形に直し、目盛りのラベルも
   0・50・100・150のように分かりやすい間隔にしてください。

3. 並び
   「今月の売上」の数値カードが画面右下の小さい位置にあります。
   これを画面の最上段、左端に大きく配置し直してください。
   グラフは数値カードの下に回してください。

変更した箇所には、どの手に対応するかをコメントで残してください。
```

3つの指示を番号で分けているのは、直した結果を後から数えられるようにするためです。

「グラフを見やすくして」だけでは、AIは色をやや薄くする程度で止まります。

軸の始点や配置の変更まで踏み込ませるには、具体的な数値と場所を書く必要があります。


## つまずきどころ

3つあります。

1つ目は、目盛りを直したのに、軸のラベルを更新し忘れることです。

棒の高さだけ計算し直し、ラベルの数字が90のまま残っていると、グラフと表示が食い違います。

2つ目は、アクセント色を複数の要素に使ってしまうことです。

最新月にも最大値にも同じ色を使うと、結局どこが主役か分からなくなります。1つのグラフには、アクセントは1箇所までにしてください。

3つ目は、並びを直すときにグラフの中身まで作り直してしまうことです。

配置の変更は、grid-template-areas の書き換えだけで済みます。グラフの計算式まで触ると、目盛りの修正と混ざって確認が難しくなります。

3つとも、直す前に一度確認すれば防げます。確認の順番は、軸のラベル、色の数、配置の3ステップです。


## 今日できること

**自分のダッシュボードで、棒グラフの軸ラベルの一番下を確認してください。**

0以外の数字が入っていたら、その時点で比率が誇張されています。

次に、同じグラフの中で使われている色の数を数えてください。

系列が1つなのに3色以上使われていたら、色を絞る余地があります。

配置は、この2つを直したあとで構いません。目盛りと色数のほうが、読み間違いに直結するからです。

軸を0にそろえ、色を絞り、最後に配置を直す。この順番で進めると、グラフを作り直さずに読める形へ変えられます。


色数と目盛りと並びは、センスの問題ではありません。数えたり測ったりできる作業です。

次にAIが出したグラフを見るときは、この3箇所から確認してください。
