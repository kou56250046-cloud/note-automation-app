# daily-article

無料記事を1本書く。**週5本（月火水金土）の主力。**

---

## `writer` サブエージェントで実行する

執筆に集中させ、判定させない。出来の良し悪しは `critic` と `auditor` が判断する。

---

## web 検索をしない

**在庫から引くだけである。** これが毎日投稿を成立させている理由である。

調べたくなったら、それは在庫の `sources` が足りていない。
その場で検索せず、`weekly-research` への申し送りとして `report.md` に記録する。

---

## 入力

| ファイル | 必須 | 何に使うか |
|---|:---:|---|
| `research/themes.md` | ○ | 今日のテーマ |
| `knowledge/account.md` | ○ | ペルソナ・カテゴリ・投稿方針 |
| `knowledge/profile.md` | ○ | **「書けないこと」** |
| `knowledge/voice.md` | ○ | 文体・禁止表現 |

1つでも欠けたら**停止して、不足ファイル名を報告する。** 推測で埋めない。

---

## テーマの引き方

```
1. themes.md から status: pending かつ day が今日の曜日のものを探す
2. 見つかった → それを使う
3. 見つからない → pending のうち type: free で最もスコアが高いものを使う
4. pending が1本もない → 停止する
```

**在庫が空のときに、その場でテーマを作らない。** 停止して `weekly-research` の実行を促す。

引いたら `notes/{slug}/00-theme.md` にコピーし、なぜ今日これを選んだかを1文添える。

`slug` は `YYYY-MM-DD-{英数字の短い識別子}` とする（例: `2026-08-10-skill-frontmatter`）。

---

## 記事の型

**1500〜2500字。** 短すぎると読まれず、長すぎると離脱する。

```
1. フック          結論を先に置く。1〜2文
2. 問題の可視化    読者が昨日か今日やった（やらなかった）動作を書く
3. 本題            手順・具体例・設定値。ここが記事の中身
4. つまずきどころ  実際に引っかかる箇所を1〜2個
5. 今日できること  読者がこの記事を読んで最初にやること。1つだけ
6. 締め            次に繋がる一文
```

### 1. フック — 結論を先に置く

```
✕ 「今回は◯◯について説明します」        → 何も言っていない
✕ 「◯◯をご存知でしょうか」              → 引き延ばし
○ 「◯◯は設定1行で解決します。3日調べた結論です」
```

### 2. 問題の可視化 — 行動で名指しする

**状態で書くと他人事になる。行動で書くと自分の話になる。**

```
✕ 「設定に困っている人」                  → 状態
○ 「同じ設定を3回書き直して、まだ動いていない人」  → 行動
```

### 3. 本題 — 具体性で価値を出す

**実績がないアカウントの無料記事は、具体性でしか価値を出せない。**

| 出せる価値 | 出せない価値 |
|---|---|
| 手順（何を、どの順で） | 「私はこれで成果を出した」 |
| 設定値・コード・コマンドの実物 | 「多くの人に効果があった」 |
| つまずいた箇所とその回避 | 「これが最も効率的だ」（比較検証していない） |
| 公式ドキュメントに書かれていない挙動 | 収益・時間削減の数値 |

**網羅しない。1点を深く書く。** 「◯◯の全て」より「◯◯のこの1箇所」のほうが読まれる。

### 5. 今日できること — 1つだけ

**3つ置くと人は何もやらない。** 1つに絞る。

---

## 書いてはいけないこと

**`profile.md` の「書けないこと」セクションを必ず読む。**
そこに列挙された主張は、言い換えても書かない。

| ✕ | ○ 代わりに |
|---|---|
| 「これで月◯万円になりました」 | 手順そのものの説明 |
| 「◯人が使っています」 | 何ができるかの説明 |
| 「作業時間が◯%減りました」 | どの作業が不要になるかの説明 |
| 「これが一番効率的です」 | 「私はこう書いている」と限定する |
| 「必ず」「絶対に」「誰でも」 | 条件を明示する（`voice.md` の ng） |

**足りないものを埋めるために創作しない。** 書かずに `report.md` に「足りない」と記録する。

**数値を伴わない作業の描写は書いてよい。**

```
○ 「毎回手でコピペしていた」          → 作業の描写
○ 「同じ設定を3回書き直した」          → 同上
✕ 「これで作業時間が半分になった」      → 成果の主張。profile.md が要る
```

---

## カテゴリの範囲を出ない

`account.md` の主カテゴリ1つ＋サブカテゴリ2〜3つの外は書かない。

範囲を出ると、その記事だけでなく**アカウント全体の推薦が弱くなる。**

---

## タイトル

**無料記事のタイトルはここで決める。**（`title-design` は有料note専用）

| 条件 | 理由 |
|---|---|
| 30〜40文字 | note の一覧で切れない長さ |
| 具体的な数字か固有名詞を1つ入れる | 抽象的なタイトルは選ばれない |
| 読者の行動を名指しする | 「自分のことだ」と感じさせる |
| `voice.md` の ng に該当しない | 煽らない。`lint.py` が検出する |

```
✕ 「効率化のすすめ」                      → 抽象的
✕ 「知らないと損する◯◯」                 → 煽り（ng）
○ 「Claude Code のスキルが起動しないとき、frontmatter の1行を疑う」
```

---

## note で崩れる記法を使わない

| 記法 | 可否 |
|---|---|
| 見出し（H2 / H3）・太字・引用・水平線 | ○ |
| 箇条書き（2階層まで） | ○ |
| コードブロック | ○（言語指定は貼付後に手動で設定する） |
| **テーブル** | **✕ note が非対応。箇条書きにする** |
| 脚注・3階層以上のリスト | ✕ |

`lint.py` が検出するが、書く時点で避ける。

## 出力

### `notes/{slug}/00-theme.md`

```markdown
# {テーマ}

themes.md の id: 2026-W33-01
選定理由: {themes.md の rationale をコピー}
今日これを選んだ理由: {曜日の割り当てどおり / 在庫の都合で繰り上げ など}

## 切り口
{themes.md の angle}

## 出典
{themes.md の sources}
```

### `notes/{slug}/01-draft.md`

本文。**タイトルは含めない**（`meta.json` に入れる）。

### `notes/{slug}/meta.json`

```json
{
  "slug": "2026-08-10-skill-frontmatter",
  "themeId": "2026-W33-01",
  "type": "free",
  "title": "Claude Code のスキルが起動しないとき、frontmatter の1行を疑う",
  "category": "Claude Code での開発自動化 / スキル設計",
  "hashtags": ["ClaudeCode", "AI活用", "個人開発"],
  "publishDate": "2026-08-10",
  "charCount": 2100,
  "createdAt": "2026-08-10T06:00:00+09:00"
}
```

**ハッシュタグは3〜5個。** 多いと薄まる。主カテゴリ由来を必ず1つ入れる。

### `themes.md` の更新

引いたエントリの `status` を `pending` → `used` に変更する。

---

## 書き終えたら

**自己評価しない。** そのまま次に渡す。

```
1. reader-feedback（critic）へ    → 離脱ポイントの検出。1周
2. ethics-line（auditor / light） → E3・E5 を検出。上限なし
3. build-report → report.md
```

「良い出来かどうか」を自分で結論しない。それは `critic` と `auditor` の仕事である。

---

## report.md に必ず記録すること

- 引いたテーマと選定理由
- **書けなかったこと**（`profile.md` に根拠がなく諦めた主張）
- `weekly-research` への申し送り（`sources` が足りなかった、など）
- 各ゲートの結果は後続スキルが追記する
