# thumbnail-prompt

**見出し画像は、記事より先に読まれる。** note のタイムラインでは画像とタイトルしか見えない。

このスキルは画像を作らない。**画像生成AIに渡すプロンプトを作る。**
生成そのものは人間が Gemini に貼って行う（ブラウザ自動操作は使わない方針）。

---

## 最も重要なこと

**抽象語だけのプロンプトを書かない。**

```
✕ 高級感、洗練、プロフェッショナル、シネマティック、ミニマル
    → どの記事でも同じ指示になる。結果、サムネが全部同じ顔になる
```

抽象語は生成AIが学習した「平均的な良い画像」を呼び出します。
**平均は、他の全員が出しているものと同じです。**

固定の技術仕様は使い回してよい。**変えるのは被写体・素材・色である。**

---

## 入力

| ファイル | 必須 | 何に使うか |
|---|:---:|---|
| `notes/{slug}/02-final.md` | ○ | 記事の主題。**被写体を決める材料** |
| `notes/{slug}/meta.json` | ○ | タイトル・カテゴリ・`demo` の有無 |
| `notes/{slug}/demo/after.html` | — | **配色。あればここから色を取る** |
| `knowledge/account.md` | ○ | サブカテゴリ。参照する美学を決める |

`02-final.md` が無ければ**停止する。** 記事が確定する前にサムネを決めない。

---

## 1. 被写体を決める（可変・最重要）

記事から**具体名詞**を1つ取り出す。抽象概念を絵にしようとしない。

```
記事: AIが出したLPのファーストビューを3箇所だけ直す
  ✕ 被写体「デザインの改善」        → 絵にならない
  ○ 被写体「暗い机の上に置かれた、2枚の板状のUIパネル」
```

### サブカテゴリごとの被写体の探し方

| サブカテゴリ | 被写体の候補 |
|---|---|
| **1. 見せられる自動化** | 画面・パネル・グリッド・レイヤー。**記事で扱った画面そのもの** |
| **2. 自動化フローの設計思想** | 繋がるノード・分岐・再試行の輪・止まった歯車と回る歯車 |
| **3. 差し替えて使うテンプレート** | 部品の並び・組み立て図・差し替えるカード・完成した装置 |

**記事に before/after があるなら、対比の構図をそのまま使う。**
2つのものが並ぶ絵は、それだけで「比較の記事だ」と伝わります。

---

## 2.5 見出しキーワードを決める（可変・文字部分）

記事のフックやタイトルから、**6〜10文字程度の核心ワード**を1つ取り出す。
説明文にしない。名詞・短いフレーズで言い切る。

```
記事: Gemini + GAS で議事録を要約する。コードとプロンプトの全文
  ✕ キーワード「議事録の自動要約について」   → 長すぎる。説明文
  ○ キーワード「議事録、要約する」           → 短く言い切る
```

before/after の記事なら「3手で直す」「3箇所だけ」のように、**手数や個数を数値で言い切る**と強い。

**この画像そのものにキーワードを大きく焼き込む。** note のタイムラインでは記事タイトルが
画像にさらに重なるが、それは気にしなくてよい。インパクトを優先する方針である。

---

## 2. 色を決める（可変）

**`demo/after.html` があれば、そこから色を取る。**

記事の中で読者が見る画面と、サムネの色が揃います。
別々に決めると、クリックした先が別物に見えます。

```
demo/after.html の :root から
  --bg    #12111b  → 背景の基調
  --amber #ffb43d  → アクセント1色
```

デモが無い記事では、`account.md` のサブカテゴリから決める。
**この場合も「落ち着いた色」「高級感のある色」とは書かない。** 具体的な色名か hex を書く。

---

## 3. 参照する美学を**1つだけ**選ぶ

複数並べると生成AIは平均を取ります。**平均は無難で、無難は埋もれます。**

**note のタイムラインはサムネの壁である。** 縮小表示で、他人の記事と横に並ぶ。
**上品にまとめた画像は、そこで消える。** 選ぶのは以下から1つ。

| 選ぶもの | どんなときに |
|---|---|
| **ポスターアート**（映画・音楽フェスの告知） | 既定。文字が主役で、被写体が背景になる |
| **強コントラストのプロダクト写真**（黒背景＋強い一灯） | 成果物そのものを見せる記事 |
| **雑誌の特集扉**（大きな見出しが誌面を割る） | 考え方・設計思想が主題の記事 |
| **技術書の図版を極端に拡大したもの** | 手順・フロー・構造が主題の記事 |

**3つ以上を並べて書かない。** 1つに決められないなら、記事の主題が絞れていない。

---

## 3.5 ド派手にする（この節が最優先）

**サムネは記事より先に読まれる。読まれる前に、まず見つけられなければならない。**

以下を**すべてのプロンプトに入れる。** 記事ごとに変えるのは被写体と色だけである。

### 画面の6割以上を文字が占める

被写体を主役にしない。**キーワードが主役で、被写体はその背景である。**

```
✕ 「右上の余白にキーワードを配置してください」
    → 添え物になる。縮小すると読めない

○ 「キーワードを画面の6割以上を占める大きさで配置してください。
    被写体はその背後に置き、文字に重なっても構いません」
```

### 色は3色まで。ただし全部を強くする

**中間色を使わない。** 背景・文字・アクセントの3色を、それぞれ最大の彩度で当てる。

```
・背景: 記事の基調色。ただし**明度を極端に振る**（ほぼ黒か、ほぼ白）
・文字: 背景の反対側。白か、蛍光色に近いアクセント
・アクセント: 1色だけ。**面で使う**（線で使わない）
```

**パステル・くすみ色・ベージュ単体を使わない。** 縮小すると灰色になる。

### 光を足す

- 文字の背後に**強い光源**を1つ置く（逆光・リムライト・ネオン管のどれか）
- 影は**硬く、濃く**する。柔らかい影は縮小すると消える
- 被写体の縁を光らせる（エッジライト）

### 斜めに置く

水平・垂直に整列させない。**文字か被写体のどちらかを 5〜15度 傾ける。**
整列した画像は落ち着いて見え、落ち着いた画像は流される。

### やり過ぎの線引き

**煽り文句は書かない。** ド派手にするのは**絵**であって、言葉ではない。

`voice.md` の `ng`（「知らないと損」「誰でも簡単に」など）は画像内の文字にも適用する。
**視覚は強く、言葉は正確に。** これが両立の条件である。

爆発・炎・稲妻・札束・ランキング風の王冠は使わない。
**内容と関係のない刺激は、クリックされても読まれない。**

---

## 4. プロンプトを組み立てる

固定部分と可変部分を分けて書く。

```
あなたは note の見出し画像を専門とするアートディレクターです。
以下の条件で16:9の画像を1枚作ってください。

## 被写体（最重要）
{ここに具体名詞。抽象概念を書かない}

## テキスト（これが主役・最優先）
「{キーワード。6〜10文字程度}」を画像内に配置してください。

・**画面の6割以上を文字が占める大きさ**にする
・極太のゴシック体（Black / Heavy 相当）。細い書体を使わない
・文字を **5〜15度 傾ける**。水平に置かない
・文字の背後に強い光源を置き、縁が光って見えるようにする
・文字色は {hex}。背景とのコントラストを最大にする
・被写体に重なっても構わない。**文字を避けて配置しない**
・縮小表示でも読めることを最優先する

## 被写体（文字の背景として置く）
{ここに具体名詞。抽象概念を書かない}

・文字の背後に置く。主役は文字である
・縁を光らせる（エッジライト）
・{before/after があるなら対比の構図}

## 色（3色まで。全部を強くする）
・背景: {hex}。**明度を極端に振る**（ほぼ黒か、ほぼ白）
・文字: {hex}
・アクセント: {hex}。**1色だけ、面で使う**（線で使わない）
・中間色・くすみ色・パステルを使わない。縮小すると灰色になる

## 質感とライティング
・{選んだ美学を1つだけ}
・**強い一灯**。逆光かリムライトかネオン管のどれか1つ
・影は硬く、濃く。柔らかい影は縮小すると消える
・高精細、ノイズなし、4K品質

## 避けるもの
・全面に敷くグラデーション
・複数の光源で影の方向がばらつくこと
・要素を3つ以上並べること
・**爆発・炎・稲妻・札束・王冠**（内容と関係のない刺激）
・**画像内に煽り文句を書くこと**（「知らないと損」「誰でも簡単に」など）
・{記事ごとに、出てほしくない定番の絵}
```

### 「避けるもの」を必ず書く

**出してほしい形より、出してほしくない形のほうが具体的に書けます。**

生成AIは放っておくと、脳のイラスト・光る回路基板・ロボットの手・
青い網目状のネットワークを出します。**名指しで避けさせるほうが早いです。**

## 出力

### `notes/{slug}/06-thumbnail.md`

```markdown
# 見出し画像のプロンプト

生成先: Gemini（画像生成）
比率: 16:9

## 判断

- 被写体: {何を選んだか}
- 色: {どこから取ったか。demo/after.html の hex など}
- 美学: {1つだけ。なぜそれか}
- キーワード: {画像に大きく焼き込む言葉。6〜10文字程度}

## プロンプト

（ここにコピーして使う全文）

## 生成後の確認

- [ ] **サムネの大きさまで縮小しても、キーワードが読めるか**（最重要）
- [ ] 文字が画面の6割以上を占めているか
- [ ] 文字が傾いているか（水平に整列していないか）
- [ ] 中間色に逃げていないか。3色が全部強いか
- [ ] 記事のデモと色が揃っているか
- [ ] **画像内に煽り文句が入っていないか**（`voice.md` の `ng` は画像にも適用する）
```

### 縮小して確認する

**等倍で見て判断しない。** note のタイムラインでの表示は小さい。
生成した画像を **200px 幅まで縮めて**、キーワードが読めるかを見る。
読めなければ、文字を大きくするかコントラストを上げて作り直す。

**プロンプト全文をコードブロックに入れる。** プレビュー画面がここを読んで
コピーボタンを出す。

## 物差し（これを満たさなければ出力しない）

| # | 条件 | 満たさないとき |
|---|---|---|
| 1 | 被写体が**具体名詞**である | 抽象概念を書き直す。「改善」「効率化」は絵にならない |
| 2 | 色に hex か具体的な色名が入っている | 「落ち着いた色」を書き直す |
| 3 | `demo/after.html` があるなら、そこから色を取っている | 取り直す。記事と色が揃わないと別物に見える |
| 4 | 参照する美学が**1つだけ** | 1つに絞る。絞れないなら主題が曖昧 |
| 5 | 見出しキーワード（6〜10文字程度）が大きく・高コントラストで配置されている | 長い説明文や抽象語を書き直す。目立たない配置をやり直す |
| 6 | 「避けるもの」に記事固有の項目が1つ以上ある | 足す。定番の絵を名指しで避ける |
| 7 | 抽象語（高級感・洗練・プロフェッショナル）だけの節が無い | 具体に置き換える |

---

## やらないこと

- **画像を生成しない。** プロンプトを作るだけである
- **ブラウザを自動操作しない。** 人間が Gemini に貼る（CLAUDE.md の方針）
- **記事を書き換えない**
- **参照する美学を3つ以上並べない**
- **抽象語を積み重ねない。** 語を足すほど平均に近づく
