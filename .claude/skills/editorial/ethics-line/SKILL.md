# ethics-line

**このゲートだけは回数制限がない。検出ゼロになるまで通さない。**

`letter-audit` と `reader-feedback` は「売れるか」を見る。このスキルは「やってはいけないことをしていないか」を見る。目的が違うので、同じエージェントに兼務させない。**必ず `auditor` サブエージェントで実行し、売るための文脈を一切渡さない。**

売る文脈を知っているエージェントは、効果のある表現を守ろうとして線引きが甘くなる。

---

## 前提の線引き

**焦らせる演出そのものはグレーではない。白である。** アウトなのは嘘だけ。

- 本物の期限を明記する → 白
- 実際に値上げする予定を書く → 白
- 3日間限定と書いて延長する → **アウト**
- 値上げすると書いて上げない → **アウト**

この区別を曖昧にして全部を削らせない。**削るのは嘘だけ。**

---

## 入力

- `notes/{slug}/02-letter.md`
- `notes/{slug}/letter-meta.json` の `deadlineClaims`
- `notes/{slug}/07-launch.md`（存在する場合）
- `knowledge/profile.md` — 本人が実際に体験したことの一覧

---

## 出力

- `notes/{slug}/ethics.json`

```json
{
  "clear": false,
  "findings": [
    {
      "id": "E1",
      "severity": "block",
      "lines": [102],
      "quote": "3日間限定",
      "why": "letter-meta.json の deadlineClaims に実行予定の記載がない。延長した場合、景品表示法および特定商取引法に抵触するおそれ",
      "fix": "実際に3日で終了する運用にするか、この記述を削除する。どちらか選べない場合は削除する"
    }
  ]
}
```

`severity` は2種類だけ。**中間評価は作らない。**

- `block` — 明らかな地雷。**必ず自動修正する。** これが1つでも残れば `clear: false`
- `review` — 判断に迷った表現。**自動修正せず人間に回す。** `clear` の判定には影響させない

迷ったものを勝手に消さないための区別である。判断基準は「嘘だと断定できるか」。断定できれば `block`、できなければ `review`。

---

## 検出項目

### E1. 偽の限定

`letter-meta.json` の `deadlineClaims` を1つずつ検証する。

| 記述の型 | 通す条件 |
|---|---|
| 「◯日間限定」 | 終了日が具体的に決まっていること |
| 「◯部で終了」 | 部数が決まっていて、到達時に実際に止めること |
| 「◯日から値上げ」 | 値上げ後の価格と実施日が決まっていること |
| 「先着特典」 | 特典の中身と人数が決まっていること |

**決まっていないものは削除させる。** 「後で決める」は通さない。

### E2. 盛った恐怖

- 恐怖が2つ以上ある → 1つに減らす
- 「もう手遅れ」に相当する記述がある → 回避可能な位置まで戻す
- 恐怖の描写が本人の体験に紐づいていない → 削除する

**E2の判定基準:** `profile.md` に記載のない地獄を描いていたら×。自分が体験していない地獄は、読者に伝わる前に嘘っぽさが伝わる。

### E3. 裏付けのない実績・体験談

- `profile.md` に無い数字が書かれている → 削除または修正
- 他人の結果を引用しているが出典が無い → 出典を書くか削除
- 「多くの人が」「みんな」など、母数のない一般化 → 具体化するか削除

**架空の第三者の声を作らせない。** これは検出したら即座に削除。

### E4. 書きっぱなしの弱点

「これはできません」と正直に書くのは正解である。ただし**書きっぱなしにすると、それが買わない理由として残る。**

- 弱点・できないことの記述を検出する
- その直後に「その代わりこうしました」に相当する補完があるか確認する
- 無ければ補完を追加させる

**これは削除ではなく追加で直す項目。** 正直さを削らせない。

### E5. 医療・投資・収益の断定表現

- 「必ず稼げる」「確実に」「誰でも100%」 → 削除
- 収益の保証に読める表現 → 「私の場合は」に限定させる
- 健康・医療に関する効果の断定 → 削除

---

## 動作

```
1. 5項目を検査する
2. findings が空 → clear: true を書いて終了
3. findings がある → 該当箇所を修正して 02-letter.md を更新
4. 再検査する
5. clear: true になるまで 3〜4 を繰り返す（上限なし）
```

**修正は最小限にする。** 該当箇所だけを直し、周辺の文章を書き換えない。

---

## 人間に必ず見せるもの

`clear: true` になっても、**検出して修正した内容はダッシュボードの自動運転ログに必ず残す。**

このゲートは自動修正するが、何を消したかを人間が知らないまま運用するのは危険である。特に E1（偽の限定）は、書いた本人が「実行するつもりだった」場合に削除が誤りになる可能性がある。ログを見て復活させる判断は人間に残す。

---

## このスキルがやらないこと

- 法的助言はしない。弁護士ではない
- 表現の良し悪しの判断はしない。それは `letter-audit` の仕事
- グレーゾーンの議論はしない。**明らかな地雷だけを踏ませない**

判断に迷う表現を見つけた場合は、削除せずに `findings` に `severity: "review"` で記録し、人間の確認に回す。**迷ったら消すのではなく、迷ったと記録する。**
