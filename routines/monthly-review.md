# monthly-review

月次でボトルネックを診断し、実績を蓄積する Routine。

| 項目 | 設定 |
|---|---|
| cron | `0 8 1 * *`（月初 08:00 JST） |
| モデル | Sonnet 5 |
| effort | high |
| 消費 | 1/月 |

## プロンプト（暫定版 — ステップ7まで）

```
このリポジトリの先月の運用を振り返ってください。

まず CLAUDE.md を読み、ルールを守ってください。
特に「実績・体験・第三者の結果を創作しない」は絶対です。
data/ に実測値がなければ「まだ数値が無い」と書いてください。推測しないでください。

## 手順

1. notes/*/meta.json をすべて読み、先月分を集計する。
   - 本数（無料 / 有料）
   - カテゴリ別の内訳
   - 週ごとの推移

2. notes/*/report.md をすべて読み、以下を集計する。
   - 各ゲートの差し戻し回数
   - ethics-line が削除・修正した内容の傾向
   - 「書けなかったこと」として記録された主張の一覧

3. research/themes.md と knowledge/learnings.md を読む。
   - 在庫の残数
   - 範囲外として却下したテーマの傾向
   - 同じ範囲外テーマが繰り返し出ていないか

4. data/ に metrics.json があれば読む。無ければ「未取得」と記録する。

5. 気づいたことを整理し、Issue を1本立てる。

## 報告に必ず含めること

- 先月の本数と目標（週7本）との差
- **ethics-line が繰り返し検出した項目**
  → 同じ項目が何度も出るなら、writer への指示か voice.md を直すべき信号
- **「書けなかったこと」の一覧**
  → profile.md が埋まれば書けるようになるものが分かる
- **範囲外テーマの傾向**
  → 同じ領域が繰り返し高スコアで出るなら、カテゴリ設定を疑う
- 在庫の残数と、補充が追いついているか

## 書いてはいけないこと

- 収益・PV・フォロワー数の推測値
- 「順調です」「うまくいっています」といった評価
  → 事実と数字だけを書いてください
```

## プロンプト（完成版 — ステップ8以降）

```
このリポジトリの先月の運用を振り返り、実績を蓄積してください。

まず CLAUDE.md を読み、ルールを守ってください。

## 手順

1. 上記「暫定版」の手順1〜4をすべて実行する。

2. profile-accumulator を実行する。
   data/metrics.json と notes/*/report.md から「言える実績」を
   knowledge/profile.md に追記する。

   出所は必ず data/ か report.md にしてください。
   出所のない数字を書かないでください。

   実績が追記できたら、profile.md の「書けないこと」から
   対応する項目を削除してください。

3. revenue-maximizer を実行する。
   顧客数 × 単価 × 購入回数 のどこがボトルネックかを診断する。

4. type: experience を解禁できるか判定する。
   profile.md に以下が揃っていれば解禁できる。
   - 天井を下げられる実績（読者が明日届く高さの数字）
   - 自分以外の結果（出典つき）

   揃っていなければ「まだ tool のみ」と報告してください。

5. Issue を1本立てて報告する。
```

---

## この Routine が最も重要な理由

**実績のない状態から始めて、運用そのものを実績に変換する。**

`profile-accumulator` が毎月 `profile.md` を育てる。数ヶ月後には
`type: experience` の有料noteを書ける材料が揃う。

それまでは `type: tool`（道具型）だけを作る。道具型は再現性の根拠を
成果物の検証可能性に置くため、実績がなくても成立する。
